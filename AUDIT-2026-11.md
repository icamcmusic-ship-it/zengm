# Feature audit: 13 features (Nov 2026)

How this was made: code reading across the 13 features. Bugs marked **✔ checked** I re-read in the code myself. The rest are from the per-feature audits and are listed with their confidence. No code was changed. Tests: a few existing test files were run (Hall of Fame 14/14, calendar 19/19, all passing). I couldn't run anything else, because the project needs Node 24 and the container has Node 22.

## 1. Injuries

**Bugs**

- Top 15 #4, #5, #6.
- **Pre-league injury seeding wasn't scaled for the new 2× injury rate.** `PAST_INJURIES_PER_SEASON = 1` (`pastInjuries.ts:15`), so new-league players start with about half the athletic loss. Career Aging and rating-inflation calibrations were also tuned at the stock rate. _High_
- **Injury Depth's `p.health` goes stale outside game days.** Offseason, free-agent and God Mode heals never call `onHealed`, so a restriction and re-injury window can carry into opening night, and free agents never tick. _High_
- **Post-injury pot drop is mostly noise and can only go down.** It comes from a random `develop(p,0)` re-estimate capped at the previous pot, so `potDrop` is biased negative even when the loss is 0. _High_ (`writePlayerStats.ts:288`)
- **The two injury messages give different lengths:** `gamesRemaining - 1` vs `gamesRemaining`. _Medium_
- **A knock can clear a real injury when there are no subs**, because the knock path checks `!p.knock` but not `p.injured`. _Low_ (`GameSim.basketball/index.ts:5076`)

**Robustness**

- A league file with an empty or all-zero `injuries` list crashes `injury()` (`cumSums.at(-1)`). Only the UI validates it.
- Custom injury names silently lose major-injury aging and body-part logic (keyed by stock names).
- God Mode injury edits add no `p.injuries` record, so hardship and `onHealed` read an unrelated old record.
- The hardship 6/3 thresholds and the Injury Depth 15-day window don't scale with `numGames`.

**Improvements:** store games actually _missed_ per injury, not just the scheduled length; update the existing record on re-aggravation; allow late-season rest for teams that have clinched or been eliminated; use one duration convention plus an "expected return" date.

**New mechanics:** day-to-day / questionable (Q/D/O) game-time decisions; uncertain recovery estimates (the medical budget narrows the range; setbacks and early returns); a surgery vs. rehab choice for major injuries; injury odds weighted by position and body type; Disabled Player Exception.

## 2. Personality

**Bugs**

- Top 15 #1 (ego inversion).
- **Two personality systems multiply the same mood components:** the F/L/$/W mood traits (`moodComponents.ts:487`) and then loyalty / role acceptance / money-vs-winning (`moodInfo.ts:66`). Up to 3.75×, enough to cross the trade-request threshold from one bad playing-time stretch. _High that it happens; whether it's intended is a design call_
- **The dunk contest reads raw `p.traits`** without `traitsEnabled()` or `completeTraitSeeds`, so the bias stays after traits are turned off. _Medium_
- **Every league created before traits shares personalities per pid,** because `playerTraitsSeed` defaults to 0. Draw a seed when traits are first enabled. _Medium/low_

**Robustness:** trade requests and holdouts use `Math.random` (`contract/unrest.ts:122, 213`) while the rest is seeded; the locker-room calc does an `indexGetAll` per moodInfo call inside free-agency loops (cache it per team per day); the aging curve is keyed by pid, so imported players get a different hidden curve.

**Improvements:** when Player Traits is on, derive F/L/$/W from the personality scores; weight the locker room by minutes or value share, not head count; name the worst egos in the mood tooltip; record technicals and flagrants as box-score stats.

## 3. Play by play

**Bugs**

- Top 15 #7 (charges).
- **Defensive-scheme lines are random per game** (`session.ts:637`), not the team's parsed coach system, and "switches to a 2-3 zone" repeats every period. _Medium-high_
- **The live game and the box-score play-by-play builder share module-level state** (`processLiveGameEvents.basketball.tsx`). Opening a stored box score during a live game resets the live flavor session. _Medium_
- **Unguarded `playersByPid[pid]!` on sub and stat events.** One missing pid (an edited or imported box score) throws, and the try/catch then hides the whole feed.

**Speed:** the sim logs PBP events for every game whenever `storePlayByPlay` is on, then throws them away for non-user games when `pbpStore === "user"`. Pass the store decision into GameSim. The same applies to `careerFromStats` / `pbpTids` in `loadTeams.ts:443-479`.

**Robustness:** add a test that every `PlayByPlayEventOutput["type"]` is handled by `describe` (`offFoul` and `elamActive` aren't).

**New:** badge-aware calls ("Limitless Range from 30 feet"), carrying `bt` through `pbpRatings`; scheme lines driven by real coach decisions.

## 6. Hall of Fame

**Bugs**

- **An un-retired ballot candidate can be stranded.** The ballot window expires without a `status`, so he's never inducted and never sent to the veterans committee, and the Watch page shows 0% (`hallOfFame/index.ts:155`, `processScheduledEvents.ts:623`). Fix: clear `hofBallot` on un-retirement. _Medium_
- **Watch and ballot disagree about the eligibility window** by one season (`watch.ts:262` vs `index.ts:140`). _Low_
- **The "Nth year on ballot" label** uses `votes.length` instead of `season - first + 1`.

**Improvements:**

- **Turning the ballot off leaves pending candidates uninducted.** Run a one-time `madeHof` catch-up.
- **The legacy team is computed two ways** (EWA with playoffs vs regular-season games). Pick one.
- **The threshold is frozen at first screening.** Recompute it so `hofFactor` changes apply.
- **`recomputeHallOfFame` wipes ballot and veterans-committee inductions.**

**New:** waive the waiting period on death (posthumous induction); announce first-ballot locks early at season end.

## 7. Player feuds

**Current state:** no lasting player-vs-player feuds. The only "feud" is a per-game map in `pbpFlavor/trashTalk.ts:336`, rebuilt each game and never saved. Team rivalries do exist and do affect games (crowd and home-court advantage, rotations, trash-talk rate). `staff/relationships.ts` (`p.coachRels`) is the model to copy.

**Proposed design** (native feature `playerFeuds`, basketball only, requires `playerTraits`; with it off, sims are identical):

- **Data:** `p.feuds?: {pid, v (0..1), kind: "teammate"|"opponent", n, s, d, src}[]` (max 4), kept the same on both players. Ended feuds become a new `"feud"` event type. The pure maths goes in `common/playerFeuds.ts`.
- **Triggers** (seeded, scaled by temper and ego):
  - flagrants and ejections, via a new `results.incidents` from the sim, consumed in `game/play.ts`
  - trash-talk jawing pairs
  - minutes disputes (`contract/unrest.ts`, `staff/rolePromise.ts`)
  - star-vs-star trade demands
  - revenge games against former teammates (`pbpGameContext.ts`)
- **Effects:**
  - a new `MoodComponents.feud` (−2..0)
  - an on-court chemistry penalty while both teammates are on the floor (`teamChemistryBonus`)
  - higher technical and flagrant rates when the pair face each other
  - the coach staggers the pair's minutes
  - the AI trade value discounts acquiring your star's rival (`aiValue.ts`)
  - news, storylines and series recaps
- **Decay:** about 10% per week, 40% in the offseason. A feud ends with retirement, a mediator (a high-leadership teammate or a players' coach), or a title won together.
- **UI:** a Relationships panel on the player page, a league Feuds view, tags in the box score and Rivalries pages, and a God Mode editor.

## 10. Calendar

**Bugs**

- Top 15 #13, #14.
- **CSV import doesn't enforce special-day rules across rows.** It allows a second deadline or All-Star game, a deadline after the deadline phase (which re-runs `newPhase(AFTER_TRADE_DEADLINE)`), and an All-Star game when disabled.
- **A stale `scheduleSpread` makes nearly every game a "3-in-4"** after realistic length is turned off and the schedule regenerated. `setScheduleFromEditor` only recomputes `scheduleDayScale` (`api/index.ts:6767`). _Medium-high_
- **"One week" / "One month" can stop short near season end:** the cap is applied in game days and then converted as calendar days (`playMenu.ts:137`). _Low impact_
- **`untilAllStarGame` / `untilTradeDeadline` aren't awaited** and throw after the deadline (`playMenu.ts:197`).

Good news: there's no `Date` math, so leap-year and timezone bugs are impossible.

**New:** a "validate schedule" panel (back-to-backs, 3-in-4s, conflicts, auto-repair); configurable All-Star break and season length; "play until day N / next holiday slate / end of road trip".

## 11. Sim speed / storage / long leagues

Measured (3 seasons, new-league defaults): DB 48.7 → 92.5 → 137 MB. Box scores level off after 3 seasons; rivalry games (3.9 MB/season) and players keep growing. One season of simming takes 39–42 s CPU; the offseason takes 13–18 s.

**Bugs:** Top 15 #10, #11.
**Biggest wins**

1. **Slim down or prune `rivalryGames`** (drop names, use tuples, keep only the top players after N seasons), and add it to Delete Old Data. Saves 60–80% of that store.
2. **Strip `pbp`/`shotLog` from old box scores that are kept forever** (playoffs, notes) in `deleteOldBoxScores`.
3. **Skip PBP event logging in GameSim for games that won't be stored** (see §3).
4. **Flush the cache every ~14 game days during long multi-day sims** (less crash loss, lower peak memory).
5. **Records Book and era baselines:** cache past seasons; read `teamStats` by index instead of `getAll`.
6. **Retired coaches are always loaded into the cache** (52 `coaches.getAll()` call sites). This matters in 100+ season and college leagues.
7. **"Age Retired Players" writes every living retired player each preseason** even when nothing changed (see §13).

**Robustness:**

- Delete Old Data should show per-store sizes and clear the `wrapped-cache` / `page-cache` databases.
- Make every direct-to-IDB write safe to repeat.
- Clear `featLedger.running` entries at retirement.
- Key the era-baseline cache by a change counter.

## 13. Faces

**Bugs**

- Top 15 #8, #9.
- **New relatives are made from the relative's _aged_ face** (`addRelatives.ts:153`), and relatives skip `styleFace` in New Face Styles leagues. _Medium_
- **Players created in Customize Player, or randomized there, are locked as "edited" and never age** (`util/faceAging.ts:185`). _Medium_
- **Age Retired Players rewrites every retired player each preseason** (random players never get `diedYear`, so the set keeps growing). _High (only when the option is on)_

**Performance:** scout faces are rebuilt on every view update by swapping out `Math.random` (`scoutingReports/index.ts:294`), and they get player-style faces that are then aged a second time; staff list pages (Coach Market, Front Offices) don't lazy-load faces; retired players' aging history is roughly 10–40 MB in long leagues, so coarsen it.

**Robustness:** the external facesjs editor round-trip can drop the fork's `fork` extras and count as an edit; `StaffFace` memo deps are missing `leagueSalt`; players created mid-season (college sim) aren't aged until the next preseason.

**New:** family resemblance in hair loss and greying (shared gene seed); ex-player coach continuity with a player → coach "Then and Now"; a "Reset to generated face" button; a roster face strip.
