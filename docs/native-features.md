# Native features

This fork adds a set of pages, tools and game-sim options to Basketball GM. The first group (Newspaper, Wrapped, Storylines, Games to Watch, achievements, Trade Grader, Timeline) used to live in the separate League Explorer app: they are built from the league's own records and run locally in the game's worker. The rest are game features (play-by-play options, a realistic possession model, player traits, injury depth, contracts, trades, drafting, coaching staff, ...).

Most of it is **basketball only**: in Football, Hockey and Baseball GM the menu items and links are hidden and the routes show a short "only available for basketball" message. The exceptions, which work in every sport, are the contract features and the trade features (the code is shared), the Draft Board and the Scouting System.

`:lid` below is the league id, as in `/l/1/...`.

## Where the pages live

Pages that belong with an original BBGM page are tabs of that page: a tab bar at the top of the page (it scrolls sideways on a phone) switches between them. Each tab keeps its own URL, which is the page's old URL, so old links, bookmarks and the command palette (Ctrl+K) land on the right tab. Tabs of a League Extras feature that is off are hidden, and the side menu highlights the host page on any of its tabs. The tab list is `src/ui/util/pageTabs.ts`; `src/ui/util/consolidatedPages.ts` lists the pages kept out of the side menu.

## League extras (feature toggles)

- **Where:** the _League Extras_ tab of League Settings (`/l/:lid/league_extras`; Tools → League Settings, then the tab). There is no separate menu or command palette item. The _League Settings_ tab leaves these settings out, and each tab saves only its own settings. The New League form still has them in its _League extras_ categories at the bottom.
- **What:** an on/off switch for every feature above, plus the options of some. A feature that is off disappears from the menus, the command palette, _More_ links, history/team/player page links and the dashboard, its pages show "turned off" if opened directly, and its background work stops (no hype computed, no achievement checks, no season odds simulations, no AI offers, no archetype updates, ...).
- **Options** (shown with their feature): hype _on Dashboard_ / _on Schedules and Box Scores_; achievement _Notifications_ / _on Dashboard_; box score play-by-play _Always show_ or _Show on button press_; _Games to Save Play-by-Play For_ (all games, my team's games, none); _Holdout Frequency_; _AI Trade Offers Frequency_ and _Expiration_; _Generate Pre-Draft Stats Automatically_; _Re-randomize New Draft Classes_; _Auto Draft From My Board_; unretirement chance, minimum age and ovr boost.
- **Sports:** basketball-only switches are hidden in the other sports (Extra Frivolities, the contract features and the trade features show there).

### Adding a toggle (for developers)

The registry is `common/nativeFeatures.ts` (root `common/`, so the build tools can use it for the league file schema); game code imports it through `src/common/nativeFeatures.ts`. Add **one entry** to `NATIVE_FEATURES`:

```ts
{
	id: "myFeature", // used in code
	key: "featureMyFeature", // game attribute holding the switch
	name: "My Feature",
	description: "One line for the settings form.",
	default: true, // existing leagues (missing attribute)
	defaultNewLeague: true, // optional, if new leagues should differ from existing ones
	sports: BBGM, // omit for every sport
	existing: true, // optional: the key is a game attribute declared elsewhere (type, default, schema), so only its form entry comes from here
	options: [ // optional
		{ key: "myFeatureSomething", name: "…", description: "…", type: "bool" | "int" | "float" | "string", default: …, min?, max?, values?: [{ key, value }] /* for string */, decoration?: "percent", existing?: true },
	],
},
```

That entry alone gives: the `GameAttributesLeague` types, `defaultGameAttributes`, the new league defaults, the league file JSON schema, the settings form entries (League extras category and page), the settings view values, the UI sync (local state) and the sport filtering. For an `existing` key you still declare it in `types.ts`/`defaultGameAttributes.ts`, and add its explicit new league default in `worker/views/newLeague.ts` (`getDefaultSettings`). Then gate the feature's code with:

- Worker: `featureOn("myFeature")`, `featureOption("myFeatureSomething")`, and for a page's view `const off = featureOffError("myFeature"); if (off) return off;` (`src/worker/util/nativeFeatures.ts`).
- UI: `useFeatureOn("myFeature")` / `useFeatureOption(...)` in components, `isFeatureOn(...)` in plain functions (`src/ui/util/nativeFeatures.ts`); menu items take `feature: "myFeature"`; for links to the feature's pages add the URL to `featureForUrl` so `MoreLinks` and `FeatureLinks` drop them automatically.

Tests in `src/common/nativeFeatures.test.ts` check that every key has a default and is synced to the UI.

## Pages built from the league's records

### Newspaper

- **Where:** League menu → _Newspaper_, `/l/:lid/newspaper`, `/l/:lid/newspaper/:team/:season` (`all` or a team like `ATL_0`). Also linked from the dashboard ("From the records"), the team pages' _More_ links (team edition), League → History and each season row of Team History.
- **What:** a front page plus sections (Playoffs, Awards, Teams, Players, Features, Transactions, By the numbers, Opinion, Colour & letters) written from the season's results, awards, transactions and box scores. During a season it reports "so far"; after the playoffs it becomes the final edition. A team edition focuses on one franchise. Back issues link to earlier seasons. _Print edition_ gives a print-friendly layout.
- **Known limits:** pull quotes and letters marked _Colour_ are invented voices (the numbers are real). Player photos load lazily as you scroll. Very old seasons with deleted box scores get fewer game stories.

### Wrapped

- **Where:** League menu → _Wrapped_, `/l/:lid/wrapped` (chooser), `/l/:lid/wrapped/season/:season`, `/l/:lid/wrapped/team/:season/:team`, `/l/:lid/wrapped/player/:season/:pid`, `/l/:lid/wrapped/all`, and `/l/:lid/wrapped/compare` (two players, teams or seasons side by side). Linked from team, player and history pages.
- **What:** a tap-through story deck (9:16 cards) of a season, a team's year, a player's year or the whole league's history. Arrow keys, the on-card buttons, tapping the left/right of the card or swiping move between slides. Each slide can be saved or copied as a 1080×1920 PNG.
- **Deck settings** (gear icon on the card, remembered per browser): number of slides, autoplay, **quiz** (a few "who led the league in…" questions mixed into the deck, with a score slide; on by default) and **no spoilers** (hides results that would give away the season's outcome).
- **Compare:** a scoreboard of the main numbers (the better value is bold with ▸), the topics both have with a winner per topic, and the slides only one side has.
- **Known limits:** the first visit to a big league builds a snapshot of the whole history, which can take a while (a progress placeholder shows; later visits use a cache, see _Performance_). Autoplay waits on an unanswered quiz question. A season that isn't over yet gets a "so far" deck without awards or playoffs.

### Storylines

- **Where:** League menu → _Storylines_, `/l/:lid/storylines`, `/l/:lid/storylines/team/:team[/:season]`, `/l/:lid/storylines/player/:pid`, `/l/:lid/storylines/all/all/:season`. _Wrapped_ and _Storylines_ buttons are on each player page; team pages and history pages link here too.
- **What:** story cards found in the league's history (Cinderella runs, upsets, droughts, dynasties, big triple-doubles, ageless wonders, ring chasers, homecomings, stacked draft classes and more), each with a _Why this story?_ button that shows the numbers behind it. The _Threads_ tab groups stories that belong together. Filter by season, kind and order, or search.
- **Known limits:** shares the Wrapped snapshot, so the first visit to a big league can take a while. Stories need history: a new league has only a handful.

### Games to Watch (hype)

- **Where:** League menu → _Games to Watch_, `/l/:lid/hype`; a _Games to Watch_ card on the league dashboard; a hype badge and reasons under games on Schedule and Daily Schedule; a hype card above box scores.
- **What:** a 0–100 must-watch score for upcoming games from what's known before tip-off, and for finished games a 0–100 game rating ("How it played out") plus a verdict comparing the two ("Did it live up to it?"). _Record chases_ lists players close to league or franchise records.
- **Pre-game signals** (each a listed reason with its points, up or down): playoff round and series state (elimination, winner takes all), play-in; two winning teams, marquee matchups (two of the league's top four), top-seed battles, playoff-line races late in the season, teams that can close in on a spot or are on the brink of elimination, tank races; rivalries (past playoff series, last year's knockout), division rivals; star power (stars, a superstar, stars on both sides); career milestones, record chases, heaters, revenge games, rookie duels, streaks, opening night. Lowering it: two losing teams, stars out injured, back-to-backs, late-season games where both teams' playoff fates are settled.
- **Game rating signals:** final margin (close up, blowouts and games over after three down; half in overtime games, which the overtime already counts), overtimes, lead changes and ties at period breaks, comebacks (bigger later), clutch plays (game-winners, buzzer-beaters, shots to force overtime, defensive game-winners if the sim records them), individual lines scored by **rarity**: each line gets one combined rarity (its rarest stat in full, the next two at a half and a quarter past the top 10%, scoring efficiency against what big scorers usually shoot, assists against turnovers, small bumps for triple- and quadruple-doubles, 5x5s, 20/20s and perfect shooting; game score as the floor), measured against the distribution of real single-game lines and scaled to the season's scoring environment; it then counts by how often a game has a line that good (a top-10% line shows up in most games and adds nothing, a 40-point night a little, a 50-point game about what a close finish does, a once-in-many-seasons line tops the scale), only the game's best line in full plus 40% of a second big one (a star duel when it came from the other side), and a small bump for the season's best single game in a stat; shootouts, team season highs (points, threes), upsets (records, seeds, team ratings), streaks ended, milestones reached and records broken, playoff context (round, series won, winner takes all, title clinched; damped in routs), and what was at stake going in. Lowering it: blowouts, ugly shooting, sloppy (turnover-heavy) and low-scoring games, two losing teams. Works from box scores alone (no play-by-play); missing shooting or turnover numbers just skip those signals.
- **Scale:** raw points map to 0–100 through percentile knots measured on simulated games, so both scores spread over the range: about half of all games under 50, one in twenty 85 or more, one in twenty 20 or less (playoff games sit higher). The tables are `src/common/hype/calibration.generated.ts`, made by `tools/hypeCalibration/calibrate.ts` from seasons simmed in node by `src/worker/util/hypeCalibration.test.ts` (off unless `HYPE_CAL_OUT` is set; see the file headers); `bbgm.hypeCalibrationDump(season)` in the worker console dumps a real league's season in the same format.
- **Verdict:** _Better than billed_ when the rating beat the hype by 20+, _Didn't live up to it_ when it fell 20+ short, else _Lived up_ (rating 50+) or _A quiet one_; the text gives both numbers and the biggest reasons (plus what happened to the pre-game story lines).
- **Known limits:** record chases need a few seasons of history. Schedule badges are only computed for the next 8 games. Career highs are not detected (box scores of whole careers are not kept); late-game flow is read from period scores and clutch plays, not play-by-play. The calibration leagues are random-players leagues simmed with the default settings.

### Best games & top plays

- **Where:** _Best Games_ tab of Daily Schedule, `/l/:lid/best_games/:season` (`all` for all time).
- **What:** the season's (or all time's) best games ranked by the Games to Watch post-game rating (`src/common/hype`, the box score's "How it played out" score) with its reasons, and the top plays: game-winners, buzzer-beaters, late go-ahead and tying shots, defensive stops (blocks and steals in the last 24 seconds of a one-possession game), posters, alley-oops, dunks, chase-down blocks, pick-sixes, heaves, and the plays that capped big runs. Plays are read from the saved play-by-play (`storePlayByPlay`) and worded by the play-by-play flavor layer, so they read like they did live; games without saved play-by-play contribute their clutch plays from the box score instead (with play-by-play saving off, all plays come from there). Ported from League Explorer's bestgames.js / topplays.js / pbp-analysis.js; code in `src/common/bestPlays` and `src/worker/util/bestGamesData.ts`.
- **Known limits:** for speed, play-by-play is read for at most 120 games a season (the best-rated ones and every game with a clutch play). All time = the best of each season with stored box scores.

### Award vote

- **Where:** _Award Vote_ tab of Award Races, `/l/:lid/award_vote/:season`.
- **What:** a simulated media vote for every league-wide regular-season award (MVP, DPOY, ROY, 6MOY, MIP, All-League, All-Defensive, All-Rookie and custom ones): 100 voters, NBA ballot points (MVP 10-7-5-3-1, other player awards 5-3-1, team awards 5/3/1 for a 1st/2nd/3rd team vote), each voter weighing the award formula, team record and scoring differently, plus availability, fatigue with the defending winner, a shared media narrative per candidate (moves the whole electorate together) and personal noise, all in units of the spread of the candidates' scores (`VOTE_PARAMS`). Calibrated on 20 seasons of a real simulated league (`awardVoteDump.test.ts` dumps, `awardVote.calibration.test.ts` reports): the MVP winner's first-place votes are typically 55–97 (median 72), unanimous votes are rare, the runner-up often gets 15–40 first-place votes, and 8–14 players get votes. Shows votes per place, points, ballot share and the narratives that helped or hurt. During the season it is the projected vote if the season ended today. Ported from League Explorer's awardvote.js; code in `src/common/awardVote` and `src/worker/core/awards/simVote.ts`.
- **Saved votes:** with `featureAwardVoteStore` (on) the vote is saved with the season's awards (`awards.simVote`) when they are given, so past seasons show the same breakdown; seasons without one show a vote reconstructed from the winners.
- **Deciding awards:** off by default, the vote is nudged to agree with the formula's winners and never changes who wins. With `featureAwardVoteDecides` on, individual league-wide awards go to the vote's winner (team awards still use the formula).

### League achievements

- **Where:** League menu → _League achievements_, `/l/:lid/league_achievements`; a _Recent achievements_ card on the dashboard; unlocks are announced as notifications.
- **Rarity:** measured on simulated random-players BBGM leagues, not on real NBA history (BBGM sims are far more generous): common more than 0.6 times a season, rare 0.15–0.6, legendary 0.025–0.15, impossible rarer. No tier that any calibration league unlocked in its first 5 seasons is impossible. The data is `src/common/leagueAchievements/calibration.generated.ts`; regenerate it with `tools/leagueAchievementsCalibration/`: `src/worker/util/leagueAchievementsCalibration.test.ts` sims a league headlessly in Node (fake-indexeddb, skipped unless `LA_CALIBRATE_OUT` is set; see its header) and records the tally every season (`sim.cjs` does the same in a headless browser against the dev server), and `calibrate.ts` turns the outputs into bands.
- **Saved state:** which tiers were already announced, and the log, are kept in the league (the `leagueAchievements` game attribute), so exporting and importing a league carries them. Older versions kept them in a separate `league-achievements` database: it is read once per league and moved in.

### Trade grader

- **Where:** League menu → _Trade Grader_, `/l/:lid/trade_grader[/:tab/:team/:season/:ws]`; grades also show on Trade Summary and the transactions list.
- **What:** each side of every trade graded by the win shares what it received produced for it. A toggle counts **regular season + playoffs** (default, `ws` = `all`) or **regular season only** (`rs`); Trade Summary and the grades on the Transactions list follow the last choice made on the grader (per browser). ### Contract value

League menu → _Contract Value_: a value index, bargains and albatrosses, and the value index shown on player salaries.

### League timeline

- **Where:** League menu → _Timeline_, `/l/:lid/timeline[/:from[/:to]]`; linked from the dashboard ("From the records") and from each season row of League → History.
- **What:** season by season (newest first): champions (with the finals result), MVPs and Finals MVPs, the newspaper's front page lead, the top 3 storylines, league achievements unlocked, records (best/worst regular season record in league history so far, single-game scoring records), the 3 biggest trades (by the trade event's importance) and comebacks. Every entry links to its source page (playoffs, player, newspaper edition, storylines season, achievement, box score, trade summary). Filters: season range (navigates), kinds (remembered per browser), team and a text search.

Entries from Newspaper, Storylines and League Achievements are left out while those features are off (the page says which). Storylines need the Wrapped snapshot: on a first visit they appear when it's ready. Achievements come from the saved unlock log, so ones unlocked before achievements were tracked in the league don't show.

### Records book

- **Where:** League History → _Records Book_ tab, `/l/:lid/records_book[/:team]` (league, or one franchise from the team dropdown).
- **What:** top 10 lists of career totals (points, rebounds, assists, steals, blocks, threes, games, seasons), single-season totals and per-game averages (70% of the team's games), single-game highs, playoffs (career, one playoffs, single game) and team seasons (most wins and losses, best and worst record, longest winning and losing streaks). Holders link to player, team and box score pages; active players get a badge, marks set this season are highlighted, records broken this season are flagged with the previous holder (and listed at the top), and season records show their progression. Franchise totals, award counts and feats are left to the stock Team Records, Awards Records and Statistical Feats pages (linked).
- **News:** with _Record News_ (`featureRecordsNews`) on, a news item and notification when a league record is broken: career total (once the old record is meaningful, e.g. 10,000 points), single-season total, single-game high or wins in a season beating a mark from an earlier season, winning streak longer than any before (10+).
- **How:** players are read once per league, season and phase and the cache's players are laid over them on each request. Single-game highs (league top 10, franchise top 3) and streaks need box scores, so they are kept as games are played in the `recordsBook` game attribute (export/import carries it); a check runs after each day of games (debounced, waits out bulk sims) and works from the box scores it hasn't seen. A league without the attribute starts from the box scores it still has, quietly (a league in its first season starts empty, so its games count from the first day).
- **Known limits:** single-game highs and streaks only cover games simmed while box scores existed; real-history imports have no older box scores. If old box scores are deleted before a check runs (a whole offseason auto-played), those games are missed.

### Milestones

- **Where:** Player Stats → _Milestones_ tab, `/l/:lid/milestones[/:team[/:horizon]]`; dashboard card _Milestone Watch_ for your team (`featureMilestonesDashboard`).
- **What:** active players within reach of a career mark (points, rebounds, assists, steals, blocks, threes, games; ladders like 10,000/12,500/... points) or of the next player above them in the all-time top 100, with the need, their pace and the projected game (game number, day and opponent from the schedule; "next season, about game N" beyond it). Horizon: this season or a season and a half. Recently reached milestones with the game they came in.
- **News:** milestones of your players are news (with a notification, `featureMilestoneNotifications`); big ones (20,000 points, 10,000 rebounds, ...) are news for anyone. Pre-game "needs N for X career" lines stay with Games to Watch.
- **How:** pace is this season's per-game rate (last season's before 10 games, else career) times the share of the team's games he plays. The same after-games check as the Records Book finds the exact game a mark was reached in.

### Rivalries

- **Where:** _Rivalries_ tab of Head-to-Head, `/l/:lid/rivalries[/:tidA-:tidB]`; the _Rivals_ card on Team History; League Stats' More links.
- **What:** one rivalry score per pair of teams (`src/common/rivalries`, gathered by `src/worker/util/rivalries.ts`): playoff meetings weighted by round (Finals most), series length and upsets; even regular season head-to-head; close games (3 points or fewer, or overtime) from stored box scores; same division (or conference); star duels (a 25+ point scorer on both sides in a playoff game); a bonus for a meeting last season and back-to-back meetings. Everything decays with a 6 season half-life. Tiers: Mild, Simmering (10+), Heated (22+), Bitter (40+). The page shows the top rivalries, Finals rivals, every Finals matchup and, for one pair, generated lines and a season-by-season timeline (record, running edge, playoff series, score).
- **Shared score:** the hype "rivalry" reason (`hypeRivalryPoints`) and the "Playoff rivalry" storyline use the same score.
- **Known limits:** close games and star duels only count seasons whose box scores are kept. Teams are by tid, so a relocated franchise stays one team.

### Series recaps

- **Where:** _Series Recaps_ tab of Playoffs, `/l/:lid/series_recaps[/:season[/:tidA-:tidB]]`; a _Recap_ link on every started series of the bracket; Rivalries timeline and Finals matchups link to them.
- **What:** per series (`src/common/seriesRecap`): headline and generated text, result with seeds, game by game (score, margin, overtime, running series score, box score links), series leaders and series MVP (best game score per game on the winning side), turning points (biggest win, biggest fourth-quarter comeback, overtime games, the swing game, the closeout, stored clutch plays), upsets by seed and comebacks in the series (down 3-1, ...). When a series ends the news item ("X defeated Y in the 1st round, 4-3") gets a line about a comeback, upset or sweep and a recap link, and is kept in the news for every round.
- **Known limits:** needs the series' box scores; older seasons whose box scores were deleted show only the result.

### Unretirements

- **What:** the old console script `tools/console-scripts/unretire.js`, built in (off by default). Once a season, when free agency starts, with the chosen chance (default 10%), one random retired player who retired at the minimum age or older (default 35) comes back as a free agent with a fresh ratings row for the season, boosted by a random 3-6 ovr (settings) by raising his non-height ratings one point at a time, favouring his strengths. Dead players, and anyone who already came back (including through the script), are skipped. A news event ("… has come out of retirement and is now a free agent") is logged and shown, and the comeback appears on the timeline.
- **Code:** `src/worker/core/phase/unretire.ts`, called from `phase/finalize.ts`.

Redraft, Draft Pick Value, Jersey Numbers by Team, Family Trees, League Economics and Home Court (the ones available in the sport). One switch hides the lot.

## Game simulation

### Play-by-play

- **Flavor (live game view):** varied, ratings-aware wording for every play (shot types, passes, fouls with personal and team foul counts, bonus situations, runs, milestones, quarter summaries). It only changes the text: game results are identical with or without it (covered by `outcomeInvariance.test.ts`). Elam ending events and shootout lines keep the original wording; clock phrases follow the league's quarter length and number of periods, and shootout lines are seeded like the rest, so a replay reads the same.
- **Career highs and milestones** (`src/common/pbpFlavor/career.ts`): "that's a new career high", "ties his career high" (final period or overtime), "N away from his career high" (final period, 25+ points, within 4), season highs, a career total reaching a round number mid-game ("that basket gives him 10,000 career points"; points, rebounds, assists, threes; regular season only), a first career triple-double, a first-year player's first career points. Points, rebounds, assists, threes, blocks and steals. What each player had done before the game (games played, career and season single-game highs over regular season and playoffs together, regular season totals, triple-doubles, age) is computed by `loadTeams` from his stats rows (`careerFromStats`: one pass over the rows, no database read), rides in the sim's init event (`pbpCareer`) and is stored with the play-by-play, so a stored game says what was true when it was played. **Nothing is said without the data:** career highs, totals and firsts need a career that is all on record (stats rows starting in the player's first season, so not the veterans a random-players league starts with) and, for highs, single-game highs in every season he played (not the historical seasons of a real-players league, which have totals only); highs wait for 20 career games (10 this season for season highs) and a minimum line (15 points, 10 rebounds, 8 assists, 5 threes, 4 blocks or steals for a career high); games stored before this have no career numbers and make no calls; never in the All-Star Game. The calls use their own seeded stream and only add a note, so the rest of the text is the same with or without them.
- **Trash talk** (`src/common/pbpFlavor/trashTalk.ts`, Temper trait, so only with Player Traits on): hotheads (temper below 45) after a dunk, an and-one, a three, a block or a steal they score from; jawing after a foul; a **feud** between two hotheads who have had words, which carries through the game (they look for each other, twice as likely to go again, "at it again" / "all night"); talking at the other bench on the way to a timeout that stops a run; the home crowd getting on a visitor who has been talking (after his miss at the line or his turnover); a calm teammate (temper 58+; "the veteran" when he is 30 or older) walking a hothead away; the player who was talked at answering with a big shot; lead-ins to technical fouls, and a second technical on the other side within a few possessions reading as the game boiling over. Technical fouls are only worded, never invented: the sim calls one technical per dead ball, so there are no simultaneous double technicals. Calm players never start anything (they only answer or step in). Chances scale with temper and context: playoffs x1.5, a **Heated** rivalry x1.5 and a **Bitter** one x2 (the shared rivalry score of `src/common/rivalries`, the same one as the Rivalries page, hype and Storylines; loaded once a season and again for the playoffs by `src/worker/util/pbpRivalry.ts` without the pass over past seasons' stored box scores, so a level is never higher than the Rivalries page shows; it rides in the init event as `pbpRivalry` and is stored with the game), close and late x1.4, a big run x1.3, a game already heated. At most 3 lines a player (5 in a feud), 8 events apart, 12 a game (16 in the playoffs, up to 6 more in a rivalry), no line twice. About 2-3 moments a game with a league-like spread of tempers, twice that in a bitter rivalry (`trashTalk.test.ts`).
- **Variety:** the most common lines (rebounds, substitutions, missed shots, free throws, steals, timeouts, period starts and ends) have about twice the phrases they had, substitutions are listed three ways, and a phrase is kept out of the next 48 picks. Over 30 simulated games (`pbpRepetition.test.ts`: lines with the same shape, names and numbers aside, as one of the previous 8 of their kind) repeats went from 5.5% to 1.3% (substitutions 16.3% to 1.1%, rebounds 5.4% to 0.8%). A later round added steal, turnover and free-throw phrases and counts the notes too: with expanded ratings and Player Traits on, steals 4.6% to 3.5%, free throws 1.5% to 1.0%, notes 3.0% to 2.6% (311 to 340 shapes), all lines 1.3% to 1.2%.
- **Storylines** (`src/common/pbpFlavor/story.ts`): at tip-off, where the teams stand (a winning or losing streak of 3+, the top or bottom of the league standings, two top-three teams; regular season, 10+ games played), a starter facing his **former team** ("back in the building where he used to play" when the former team is the home team) and, in the playoffs, a starter with the Big Game trait; a rookie's **debut** (starting, or his first time checking in; needs a career that is all on record with no games in it); "making his old team pay" (20+ points in the final period). Calls from what a player is known for, each checked against the play: **catch-and-shoot** (assisted jumper, csh 70+) and **off-the-dribble** (unassisted pull-up/step-back/fadeaway, dsh 70+) jumpers, the **offensive glass** (his 3rd+ offensive rebound, oreb 68+, the count is his own), **length** (blocks and steals, wng 72+), **lockdown** perimeter defense (steals and blocked jumpers, pdef 72+), an **interior wall** (blocks inside, idef 72+), a guard **switched onto a big** who blocks him (Defensive Versatility 70+), a **motor** still running in the final period (breaks, putbacks, steals; Motor 75+), **ball security** (7+ assists and no turnovers in the final period, bsc 65+), a **leader** (Leadership 75+, "the veteran" at 30+) rallying the group at a timeout called against an 8+ run or before the last period of a close game, a **big-game** player reaching 25/30 points in the playoffs, a **closer** (Clutch 75+) scoring in the last two minutes of a close game, **garbage time** (final period, 6 minutes or less, 25+ lead, the leader going to its bench) and the **bench** reacting when a garbage-time reserve hits a three or a dunk. Expanded ratings come only with that setting on, traits only with Player Traits on; nothing is said without the data. Records, streaks, ranks and former teams are read once per day of games by `src/worker/util/pbpGameContext.ts` (pbpGame on the home team, `former` with the player's ratings; former teams from his regular season stats rows) and stored with the game, so a stored game also shows the "X (10-5) host Y (8-7)" line live games had. Own seeded stream, no shared variety memory, only adds a note; spaced out (6+ events apart, at most 3 a player and 14 a game besides the tip-off and once-a-game calls); never in the All-Star Game (`pbpStory.test.ts`). Not done, for lack of data in the sim: a first game back from injury, coach's challenges beyond the existing wording, a separate color-commentator voice.
- **Stored format** (`src/common/pbpFlavor/store.ts`): version 3 adds the rivalry level and each player's career numbers to the header (about 8 KB a game); version 4 adds the game context (records, streaks, ranks) and each player's extra ratings and traits for the storylines (about 8.5 KB a game); versions 1-3 still decode and read without those calls.
- **Clutch plays:** game-winning, game-tying and overtime-forcing shots (box score notes, news feed, player events) use the flavor wording too ("X buries a step-back three, set up by Y, with 2.1 seconds left to win it"), with the shot type, assister and defender taken from the sim's own clutch-play record (`meta`), so it works with play-by-play logging off; seeded by gid and the play's index (`src/common/pbpFlavor/clutch.ts`). **Game-saving defensive plays** are recorded the same way: a block, steal or forced turnover (credited to the man guarding the ball handler) in the last 10 seconds of the 4th quarter or overtime, with the defense tied or ahead by no more than the offense could have scored on that play (2, or 3 for a three-point try or a turnover), kept only if that team wins in that period and the offense never scores again. Not under Elam endings. The sim has no charges/offensive fouls, so none are recorded. About 70-90 shots and 35 defensive plays per 1,230-game season (`clutchFeats.test.ts`); no random numbers are used.
- **Live play-by-play** (`pbpLiveGame`): show the feed when watching a game live. When off, the score, clock and box score still update.
- **Box score play-by-play** (`featurePbpBoxScore`, option `pbpBoxScore`): _Always show_ the play-by-play as a box score tab, or _Show on button press_ (the text is only made after pressing _Show play-by-play_, remembered per game for the browser session). When the switch is off, box scores have no play-by-play at all.
- **Save play-by-play** (`storePlayByPlay`, option `pbpStore`): which games keep their play-by-play with the box score: _All games_, _My team's games only_, _None_. About 7 KB per game, deleted with the box score. `storePlayByPlay` off (the old on/off setting) still means _None_ and is kept in step with the scope by `setGameAttributes`. Helpers and tests: `src/common/pbpSettings.ts`.
- **The sim never depends on any of it:** the same seeded game gives the same box score with logging off, stored and live (tests in `outcomeInvariance.test.ts` and `playerTraitsSim.test.ts`).
- **Known limits:** the wording assumes 12-minute quarters for some clock-based phrases.

### Game simulation options

- **Technical & flagrant fouls** (`technicalFouls`): rare technical fouls (1 FT, possession unchanged), flagrant fouls (2 FTs and the ball) and ejections.

### Realistic possession model

`realisticPossessions`. Possessions play out like in the NBA: a 24-second shot clock (14 after an offensive rebound), fast breaks and half-court possessions, late-clock shots and shot-clock violations, holding for the last shot, 2-for-1s, and intentional fouling late in games. Box score averages stay about the same (`possessionMetrics.ts` prints a before/after table: `POSS_METRICS=1`). Code: `src/worker/core/GameSim.basketball/possessionModel.ts`. Every random number it draws is drawn only when the setting is on. Player traits feed its shot discipline and consistency hooks (see below).

### Player traits

- **Where:** player pages (a Traits line on the Overview and a **Traits** sub-page, `/l/:lid/player_traits/:pid`, in the player dropdown next to Overview and Game Log), Draft Scouting (Traits column), Advanced Player Search (Traits filters and columns), Customize Player in God Mode (trait sliders), and the game sim.
- **What:** twenty-two 0-100 traits in four categories: Mental (clutch, late-game IQ, big-game, consistency, shot discipline, foul discipline, handle under pressure), Personality (leadership, ego, temper, work ethic, veteran savvy, loyalty, role acceptance, money vs winning), Physical (durability, recovery, motor; the secret aging curve only after retirement) and Playstyle (off-ball movement, screens, hustle, defensive versatility), derived from ratings, age, experience and a stored per-player random component. Prospects' traits are estimates that sharpen with scouting and with seasons played. In the game sim they nudge shots, turnovers, fouls, steals, free throws, fatigue recovery, team synergy, end-of-game decisions and injuries by small amounts (veteran savvy also mentors young teammates: a zero-sum preseason progression bonus of up to +-0.5 ovr) that average out league-wide (10,000-game table in `docs/player-traits.md`). With the setting off the sim is byte-for-byte what it was.
- **AI uses traits:** with the setting on, AI teams multiply a player's (positive) value by a bounded trait factor (1 ± 7% at the extremes, typically ±3%) in trade valuation (`ValueChangeCalculator`), free agent signing order (`freeAgents/autoSign.ts`), contract demands (`normalizeContractDemands.ts`, half strength) and the draft (`runPicks.ts`, a nudge capped at ±1.5 value points). Only the part of each trait not already explained by ratings counts, so the AI doesn't pay twice for ratings; durability (injury proneness / iron man) weighs most, then veteran savvy, leadership, clutch, shot discipline and the rest. Veteran savvy is worth 1.5x to contenders and more to teams with young players to mentor, half for young players themselves. **Team context for the newer traits:** work ethic counts 1.5x for players 24 and under (0.4x at 30+) and another 1.3x to rebuilding teams; big-game counts 1.5x to contenders and 0.6x to rebuilding teams; ego counts 40% more for each big ego already in the team's locker room (ego z ≤ -0.5, up to 3) and another 1.5x to a contender whose locker room is fragile (teammates' ego z sums to -1 or less); temper counts 30% more per hot head already on the team (up to 3) and 1.4x to contenders. So AI teams are warier of trading for, signing or drafting a second or third diva or hot head. These scale the trait's weight in both directions (the same locker room pays more for a team-first or composed player), which keeps the average at 1, and they are computed from the player's teammates only, never himself, so a team values its own player the same going out as coming in. The whole factor is still capped at ±7%. Contract demands have no team context. The secret aging curve has no AI weight. Roster context: `getAiTraitTeamContext` / the `team` option, constants in `AI_TEAM_TRAIT_CONTEXT`. AI teams know pros' true traits; draft prospects are read through the same fixed scouting error the user sees (hidden traits count half). The same factor applies to players coming in and going out, so it can't be arbitraged. Measured: factor averages 1.002 over a random league (contract factor 1.001), so value and pay levels don't drift. With the setting off it is exactly 1. Code: `common/playerTraits/aiValue.ts`, `player/traits.ts` `getAiTraitValueFactor`. Tests: `aiValue.test.ts`, `aiTraitValue.test.ts`.
- **Development, personality:** _work ethic_ makes young players develop more and every player's bad years smaller (preseason, centered on the league so ratings don't inflate); _big-game_ shifts shooting, free throws and turnovers in every playoff game; _ego_ adds a **Locker room** mood component for teammates (team-first lifts it, divas drag it down), on-court chemistry, and makes divas quicker to ask for trades; _temper_ means more technicals, flagrants and ejections (Technical Fouls setting), worse late-game composure, and trash talk in the play-by-play text (hotheads only, cosmetic: after big plays, jawing and feuds with opponents, the crowd, a lead-in to their technicals; more in the playoffs and in heated or bitter rivalries, see Play-by-play). A secret **aging curve** (early bloomer, late bloomer, aged gracefully, normal) moves when a player develops and declines; it is never stored or shown (not in scouting, badges, pot, projections, exports, God Mode or the AI's valuation) until the player retires, when his Traits page reveals it.
- **Loyalty, role acceptance, money vs winning, motor, defensive versatility:** loyal players ask up to 8% less to re-sign with their team, are happier staying and ask for trades less (disloyal ones the opposite, more likely to test free agency); role acceptance scales the playing time mood penalty (0.5x-1.5x) and trade requests over minutes; ring chasers are pulled more by winning teams and take up to 15% less to join a contender (minimum contract rules unchanged); motor scales on-court fatigue (+-10%) and back-to-back endurance (+-5%); defensive versatility adds up to +-1.2% to team defense against big/small lineups. Bounded, centered, pure sim.
- **Traits page:** sections per category; each trait shows one line about the player's current status by level ("Rises in the final minutes of close games"), phrased as a scouting estimate ("Scouts think he ...") or "Unknown" while uncertain; the general descriptions are in the legend.
- **Details:** `docs/player-traits.md` (data model, hook table, how the sim applies each hook, calibration).

### Injury depth

- **Setting:** `injuryDepth`. On for new leagues, off for existing leagues (they play exactly as before).
- **What:**
  - **Minutes restriction on return:** after an injury of 5+ games, a player comes back on a restriction for about a third as many days (2–10), starting at ~55% of his normal playing-time weight and easing back to 100%. It goes through the same knob as the roster page's playing time setting, so the rotation code respects it.
  - **Re-injury risk:** for 15 days after any injury of 2+ games the injury risk is higher (up to 1.8×, fading), and a new injury has a 45% chance to be to the same body part.
  - **Injury-prone players:** about 7% of players (fixed per player), plus anyone with 5+ injuries of 3+ games in the last three seasons, get hurt 1.4× as often. Shown as a badge on the player page.
  - **Back-to-backs:** the second night of a back-to-back (regular season) has 1.15× injury risk and slightly lower endurance (more fatigue in the game). Marked **B2B** on Schedule and Daily Schedule.
  - **Load management:** on the second night of a back-to-back, AI teams rest veterans in their top 8 (34+, or 31+ and injury prone) when they have at least 10 healthy players. For your team, turn it on for the whole team on the Roster page (below Play Through Injuries) or for single players on their player pages.
  - Everyone's base rate is scaled by 0.9 so league-wide totals stay about the same.
- **Player page:** the Injuries section adds a body-part history (injuries, games missed, last season) and, with the setting on, the restriction / recently returned / injury-prone status and the load management checkbox.
- **Known limits:** the countdowns are per day (like BBGM's injury countdown), not per game played. Resting is decided when the teams are loaded, so a rested player shows as not playing in the box score. With player traits on, a player's durability trait multiplies his injury rate on top of this.

### Expanded ratings

- **Setting:** `expandedRatings` (League Extras → Players). On for new leagues, off for existing leagues, which then play exactly as before (byte-identical generation, development and games: `expandedRatingsOff.test.ts`, recorded before the feature).
- **What:** three more ratings (and five more in a second step, below). **Wingspan** (`wng`, "Wng"): length, on the same scale as height (an average ape index gives wng = hgt), drawn at generation around height (sd 6.5), then fixed (it only grows with height, and a little in some teenagers). **Perimeter defense** (`pdef`, "PDf") and **interior defense** (`idef`, "IDf"): they replace defensive IQ in the game sim; `diq` is kept as their average, so ovr, AI value and every other formula that reads diq still works. Guards lean perimeter, bigs interior (point +12, center -13 on average); with age the split drifts toward interior defense (perimeter defense is legs, interior is size and positioning), symmetrically, so diq ages exactly as before.
- **Game sim** (pure sim, no play-by-play dependence): the defense, perimeter defense, interior defense, blocking, stealing, rebounding, jump ball and at-rim finishing composites read the new ratings (`EXPANDED_COMPOSITE_WEIGHTS` in `common/expandedRatings.ts`); shots at the rim/post are contested by interior defense and jump shots by perimeter defense (each mixed half and half with the team defense); blocks at the rim depend on the shooter's length (finishing over defenders). Calibration constants at the top of `GameSim.basketball/index.ts`.
- **Ovr:** a quarter of height's weight goes to wingspan; diq is the defense average. League ovr/pot distributions are unchanged (wng averages hgt).
- **Existing leagues:** turning the setting on derives the ratings deterministically (seeded by pid) for every player who isn't retired: wingspan from height plus how much he rebounds and leaps for his height, plus noise; the defense split from speed, height, strength and ball handling plus noise, around his current diq (so diq doesn't change). Then ovr, pot and skills are recomputed. Retired players' old rows are derived when shown. Real player leagues and league files without the ratings get them the same way at league creation. Turning it back on later moves each player's perimeter/interior defense to his current diq (keeping his split), since diq kept developing without them.

- **Second step (same setting): five more ratings.**
  - **Offensive / defensive rebounding** (`oreb` "ORb", `dreb` "DRb"): they replace `reb` in the game sim and `reb` is kept as their average (exactly like diq with the defense ratings), so ovr and everything else that reads reb is unchanged. Athletic, strong bigs lean to the offensive glass, smart players box out; with age the split drifts toward defensive rebounding (symmetrically, so reb ages exactly as before).
  - **Catch-and-shoot / off-the-dribble** (`csh` "C&S", `dsh` "OTD"): how a player gets his jumpers. Design: `fg` (mid-range) and `tp` (three) stay the _range_ ratings and are kept as compat values, with the invariant `csh + dsh = fg + tp` (`syncShootingToFgTp`). So a player's average jump shooting is exactly his old fg/tp level, and the split only says whether it comes off a pass or off the dribble. Ball handlers and fast players lean off the dribble, bigs and non-dribblers spot up. In the sim an assisted jumper (mid-range or three) gets `+ gap / 2`, an unassisted one `- gap / 2` (gap = csh - dsh, as a composite, times `EXPANDED_JUMPER_STYLE`), on top of the stock fg/tp composites. Customize Player: editing csh/dsh moves fg and tp by the difference (keeping fg - tp), editing fg/tp re-splits csh/dsh (keeping csh - dsh).

Sim: the turnover denominator is 60% the team's ball security composite (bsc, plus a little drb, pss, spd) and 40% the stock dribbling/passing; who commits the turnover reads bsc too. No compat value; ovr gives it a fifth of drb's weight.

### Season odds

- **Where:** _Standings_ (a _Season odds_ section below the tables), _Power Rankings_ (Playoffs and Title columns), _Award Races_ (a Win% column), _Draft Lottery_ (a _What-if simulator_ below the lottery table).
- **What:** 1,000 Monte Carlo simulations of the rest of the season in the worker: each remaining game is decided from team strength (team rating from the current roster, ignoring injuries of 10 days or less, blended with point margin as games are played) plus home court, playoffs are seeded with the game's own playoff code, then the play-in and the bracket are played out. Gives projected record, playoff and play-in odds, seed distribution, reaching the semifinals/finals and title odds. During the playoffs it plays out the remaining series from the current state. Results are cached and refreshed after each day of games, trades, signings or injuries (about 0.2 s per refresh), and only when a page that shows them asks.
- **Award races:** each candidate's award score (BBGM's award scoring) is projected to the end of the regular season with noise that shrinks as the season goes on, and the winner drawn 5,000 times.
- **Lottery what-if:** move teams up or down the lottery order (chances stay with the slot) or pick another lottery format, then _Run lottery_ for exact odds (where fast enough), a 20,000-lottery simulation (hover a cell) and one sample draw.
- **Known limits:** current season only. Tiebreakers are approximated (random among tied teams) and playoff reseeding is ignored. Award odds only consider the top 10 candidates shown and don't model team record changes. The what-if ignores nba2027 restrictions and COLA when switching formats; in the other sports (no Season Odds there) it goes with the _Extra frivolities_ switch.

### Archetypes

- **What:** a 2K-style archetype for every basketball player (243 of them: Floor General, Sharpshooter, 3-and-D Wing, Stretch Four, Rim Protector, Point Center, Jumbo Playmaker, Corner Specialist, Stretch Rim Protector, Point of Attack Defender, Three-Level Scorer, Two-Way Stretch Big, Triple-Double Threat, Lob-and-Block Big, Glass-Cleaning Playmaker, Defensive Quarterback, Inside-Out Big, Two-Way Creator, ... plus role players (Backup Point Guard, Rotation Wing, Backup Center, Journeyman ...), raw prospects (Raw Athletic Wing, Project Big, Shooting Prospect, ...), veterans (Veteran Floor Leader, Crafty Veteran Guard, Veteran Defender, Veteran Big, ...), star types (Playmaking Superstar, Athletic Superstar, Elite Shotmaker, Two-Way Superstar, Dominant Big) and rare "unicorn" types), **derived from his actual ratings**, with an optional hybrid partner ("Slasher / Playmaker"), a tier by overall within the league, a confidence and a "why" (the three ratings groups that fit best). Engine: `src/common/archetypes/` (profile scoring over BBGM's composite ratings, height gates, **position priors**, signature skills, league percentiles).
- **Position prior:** his BBGM position (PG, G, SG, GF, SF, F, PF, FC, C; the game's own formula or, with [Improved positions](#improved-positions), the two-axis model, both in `position.ts`) is a strong prior. Each group (guard/wing/forward/big) has a per-position nudge, archetypes can override single positions (a Big Guard may be a GF, a Small-Ball Five an F), and some pairings are never allowed whatever an archetype says: PG/G/SG/GF are never bigs, PG/G never forwards, F/PF/FC/C never guards. A player's match is read against his peers (same height gate, allowed positions), and the stored label uses the position the game shows, so scouting fuzz cannot push him across. The calibration that evens out how often each archetype is picked is capped at ±0.25 (it was ±0.6): correctness over evenness. In a small league, an archetype with too few peers reuses the reference league's table instead of being read against everyone (that was what labelled some point guards Towering Center). Diagnostics: `RUN_ARCHETYPE_DIAG=1` on `diag.script.test.ts`.
- **A label must deliver what its name says (defining-skill gates):** every dimension an archetype weights at 2 or more must actually be there (at least ordinary for his size and above his own norm), and names carry absolute floors (`NAME_NEEDS` in `defs.data.ts`): a shooting label needs real three-point shooting, a rim protector real shot blocking (not just height), a playmaker real passing, an athletic label real athleticism, rebounding/post/slashing labels the skill for his size. A shortfall costs fit in proportion (`score.ts`), so the label goes to the next archetype that does fit. Prospects well below the league's level get proportionally lower floors (a promising shooter at 19 is still a shooter). Being even better than a profile asks at a skill it wants no longer counts against a fit (an elite shooter is still a shooter), and size-driven skills (blocks, interior defense, rebounding, rim and post scoring) are read partly in absolute terms.
- **Lifecycle archetypes:** raw prospects and journeymen are gated on his overall level (well below the league's), raw prospects also on age (24 or younger); veterans need his age (31+, never picked when the age is unknown, so not for draft prospects or regeneration targets). Their tables always come from the reference league, which includes a draft class of prospects.
- **Star archetypes:** five labels gated on an overall level well above the league's (`level: [1.1+, 9]`) and elite absolute usage, each with floors on what makes him elite (passing and IQ, athleticism and rim finishing, mid-range and free throw touch, two-way defense, post scoring plus fouls drawn plus rebounding). They get a small bonus (`STAR_BONUS` in `classify.ts`) over the generic scorer labels every star also fits, so superstar forwards no longer all read as Scoring Forward (2025: LeBron James Playmaking Superstar, Giannis Antetokounmpo Athletic Superstar, Kevin Durant Elite Shotmaker, Joel Embiid Dominant Big). Their `need` floors keep the full size-relative checks (only low level gates, raw prospects and journeymen, read a player against himself).
- **Standout skills:** a label should name what stands out about him. His skills are grouped into the classes a label can promise (shooting, mid-range, finishing, post play, handle, passing, rebounding, rim protection, perimeter defense, athleticism); the classes he is best at for his size (a raw prospect or a journeyman partly against himself; defense only with the instincts to match) are his standouts. An archetype whose profile features them (weight 2 or more in full, 1.5 half) gets a bonus (`STANDOUT_K` in `score.ts`, only when he fully qualifies for the label, never for raw prospect, journeyman or veteran labels), broad labels (Scoring Forward, Rotation Wing, Sixth-Man Scorer, journeymen, ... tagged `generic`) pay for each standout they leave out (`GENERIC_K`) and are never pushed up by the calibration, and the hybrid partner prefers a runner-up that names a standout the primary does not (`SECONDARY_K` in `classify.ts`). 21 new archetypes fill the skill pairs no label named (two-way guards and wings, Triple-Double Threat, rebounding, post and glass-cleaning playmakers, Grab-and-Go Forward, lob-and-block forwards and bigs, Defensive Quarterback, inside-out scorers, stretch playmakers, Athletic Scorer, Rebounding Stopper, Perimeter Big, Shot-Blocking Prospect). Stickiness is 0.5 (was 0.4) so more, closer archetypes do not flap more from season to season; the level slack on skill floors (a promising shooter at 19) now fades out from age 23 to 27 except for veteran labels. Diagnostics add an independent **descriptor agreement**: each player's top two standout skills, read as z against the population's players at his position, and the share of them his label (primary + secondary) names. Before/after (seeded diagnostics populations): descriptor agreement 45% → 55% of a random league, real NBA ratings 40% → 47%, veterans 34% → 43%; "a clearly more descriptive archetype was within reach" 15.6% → 10.4% (real 13.8% → 11.1%); elite shooters not labelled as shooters (real) 13 → 3; label-vs-ratings mismatches 0.47% → 0.27% of a random league, real NBA 0.51% → 0.35%, draft prospects 0.27% → 0.27%, veterans 0.13% → 0.00%; 0 hard position conflicts; max share 2.6% → 2.6% (real NBA 3.6% → 3.4%); year-to-year changes 13.5% → 12.8% of seasons. The diagnostics now seed BBGM's generator (and the calibration sample), so the numbers are the same run to run.
- **Two-way players, passing bigs, fewer hybrids:** a label that features both his best skill on offense and his best on defense gets `TWO_WAY_K` (read apart from the standouts, which fade out next to an elite scoring skill; defense needs the instincts too, and finishing does not count as offense for a big body), and a big body who passes well gets `PASSING_BIG_K` for a label that features passing (`score.ts`). Grab-and-Go Forward now features passing (half). A hybrid partner is named only when it adds a standout the primary does not (`SECONDARY_MIN`) or is all but tied with it, so a single strong label is the norm. Diagnostics add stricter checks (a passing big: a PF/FC/C with passing among his top two standouts; a two-way player: top two standouts are a skill on offense and a defensive one backed by defensive IQ). - **With expanded ratings:** players who have wingspan and perimeter/interior defense (the [Expanded ratings](#expanded-ratings) setting on) are read with them, against a second reference league generated with the setting on (`normsExpanded.data.ts`). Three more dimensions: `pdef`, `idef` (the ratings themselves) and `len` (wingspan relative to height). ### Improved positions

- **What:** basketball positions (PG, G, SG, GF, SF, F, PF, FC, C) from two axes instead of BBGM's one PG-to-C line. **Size** = height (dominant) plus strength, rebounding, inside scoring, jumping and defensive IQ; **ball skills** = passing, dribbling, three point shooting, speed and offensive IQ. Each is turned into a percentile against a fixed reference distribution (generated players), so positions do not drift with the league. The nine positions are centroids in that square (PG small/skilled, C big/unskilled, FC a big with skills, PF a big without, F/GF/G hybrids) with a per-position bias fitted on sticky careers so overall shares stay within about half a point of the old formula. Tall playmakers become F/FC rather than C, small bigs PF/F. Code: `improvedPosition`/`positionFor` in `src/common/archetypes/position.ts`; fitting and diagnostics: `RUN_POSITION_FIT=1` on `positionFit.script.test.ts` (`FIT=1` refits the biases).
- **Stickiness:** when a player develops he keeps his current position unless another one is closer by a margin (0.02 in squared percentile distance). Position changes per player-season: about 5-6% (old formula ~6%, the two-axis model without stickiness ~13%).
- **When positions change:** for new players at generation, and when players develop (preseason, or a God Mode edit). Rows of earlier seasons are never rewritten. Custom string positions (`p.pos`) are untouched. As before, positions come from true ratings (not scouting fuzz).
- **Archetypes:** the stored position is the archetype prior (hard blocks unchanged: same nine labels); prospects' live labels and the ratings regenerator read the position the game would assign. Forbidden archetype/position pairings: 0; odd pairings 0.3% (0.8% with the old formula).
- **Setting:** on for new leagues, off for existing ones (off = the original formula, exactly). Turning it on in an existing league takes effect as players develop; mid-season, a player whose position is recomputed (e.g. a God Mode edit) may move to the new model before the preseason.
- **Known limits:** the archetype engine's built-in reference tables (`norms.data.ts`) were built with the old positions; league norms use the stored positions.

## Contracts, mood and player unrest

Unlike most of the pages above, these work in every sport. Switches are in League Extras; on for new leagues, off for existing leagues until turned on.

- **Options and partial guarantees** (_Contract Options & Guarantees_): the negotiation window has _Option_ (player option −5%, team option +10%) and _Guaranteed after year 1_ (100/75/50/0%, up to +20%) pickers for contracts of 2+ years. AI teams put terms in some of their deals too. Options are decided at the start of the re-signing phase: players opt out when the market pays more (or they're unhappy and wouldn't lose much), teams keep a team option if the player is worth about what he'd be paid. A declined option makes the contract expire then, so the player can be re-signed like any expiring contract. You can exercise or decline your own team option early from the player page. Releasing a player only owes the guaranteed part of seasons after the current one, and not an undecided team option. Contracts show a _PO_/_TO_/_%G_ badge next to the expiration year.
- **Extensions** (_In-Season Contract Extensions_): players in the last 2 seasons of their contracts can be extended in the preseason and regular season, from _Negotiate extension_ on the player page. The new seasons are added after the current ones, so this season's payroll doesn't change. Willingness comes from mood. AI teams extend some good players in their final season, but not into the luxury tax (soft cap) or over a hard cap, and try to settle a holdout with an extension (25% a day per team; into the tax only for one of the team's two most valuable players). Extensions can be undone like signings.
- **Mood transparency** (always on): the player page _Contract & Mood_ panel (collapsed by default with a one-line mood / willingness summary in its header; click the header to expand, and the choice is remembered in this browser; trade request and holdout notices stay visible) shows contract seasons with guaranteed amounts and options, release cost, a _What would make him re-sign?_ table (projected willingness if the team wins, after a deep playoff run, with a bigger role, with no more trades, or all of these), and mood history with sparklines. Mood is snapshotted at the trade deadline, at the end of the regular season and after the playoffs (up to 30 per player, in `p.moodHistory`).
- **Free agent demands** (always on): during free agency and the season, a free agent with no market comes down faster than the stock daily decrease (which is tiny next to modern salaries). Below replacement level (the median AI team's last-man value) he gives up half of what he asks above the minimum each day in the regular season (12% a day in free agency), so he's at the minimum within about 5 days. A better player who asks more than his share of AI cap space (the best free agent is matched with the most cap space any AI team with a roster spot has, the second best with the second most, ...) gives up 35% a day (8% in free agency, so about a week in the season), but not below that cap space, so players a team could still pay keep their price. Over-the-cap AI teams only sign minimum contracts in either cap mode; with no salary cap only below-replacement players drop fast. A free agent at the minimum still refuses a team he really hates (mood components summing below -8) until enough days unsigned bring him around. Code: `freeAgents/decreaseDemands.ts` (`getDemandMarket`); `FA_METRICS=1` on `decreaseDemands.test.ts` prints a day-by-day table.
- **AI re-signing and the luxury tax** (always on, soft cap with a luxury tax): in the re-signing phase AI teams don't re-sign a player into the luxury tax unless he's one of the team's 3 most valuable players (draft picks are always signed). Teams kept drifting into the tax over a few seasons before (the AI only asked whether the team was better with him). Code: `AVOID_TAX_MIN_RANK` in `phase/newPhaseResignPlayers.ts`.
- **Free agent market** (always on): the Free Agents page _Market_ column shows how many AI teams are interested and the chance he signs elsewhere on the next day; click it for each team's interest (top target, next in line, fallback), the per-day chance and the most likely team. This mirrors how AI teams sign free agents (each day, a team that doesn't skip signs the best player it can fit).
- **Trade requests** (_Trade Requests_): very unhappy stars (top 15% by value) can ask to be traded, checked about weekly in the regular season. It's in the news, AI teams value him 15% lower when trading him away, and the trading block shows a _Trade request_ badge. AI teams actively shop a player who asked out (with _Need-Based AI-to-AI Trades_ on): see Trades. Requests end when he's traded, extended, or happy again.
- **Holdouts** (_Holdouts_, option _Holdout Frequency_, 0 for none): before the regular season, unhappy players paid well under their market value with 2+ seasons left may hold out, missing a few games (scaled to season length). An extension or a trade ends it early; holdouts also end with the regular season.
- **Data:** contracts gain optional `option`, `guaranteed` and `extensions`; players gain optional `moodHistory`, `tradeRequest` and `holdout`. Nothing needs migrating.
- **Known limits:** what-if projections hold everything else fixed. Market odds are for the next day only and assume teams keep their current needs. Holdout players sit out like injured players.

## Trades

Unlike most of the pages above, these work in **all sports** (the trade code is shared).

- **Why the AI said no** (_Trade Explanations_): on the Trade page, when the AI rejects a proposal or answers _What would make this deal work?_ with a counter, a _Why?_ link under the GM's message lists, per asset, the terms the AI used: talent level, age and strategy (rebuilding teams value youth and picks more, contenders discount potential), contract (overpaid/bargain/expiring; rebuilding teams weigh contracts more), injuries, projected pick position, plus team-level terms: strategy, roster fit (team ovr before → after) and payroll/cap space. Built from `ValueChangeCalculator.explain()`, the same math the AI decides with.
- **Need-driven AI-to-AI trades** (_Need-Based AI-to-AI Trades_): contenders buy veterans in the run-up to the trade deadline, rebuilding teams sell veterans for picks and young players, and teams paying luxury tax dump contracts into teams with cap space (with draft picks as sweeteners). Over-the-cap buyers send back salary filler. A team whose star has an active trade request shops him to the other AI teams (contenders and winning teams likelier; the buyer keeps only its 2 best players off the table), and the trade text says the request was granted. When a buy/sell or trade request deal is blocked only because the buyer can't send enough salary back, half the time a third AI team with cap space takes the buyer's salary filler (for one of the buyer's picks if it wants one) while the seller is paid in picks (_Three-Team Trades_ on; every team must like its part and the cap rules hold for each team's totals). Recorded as one trade event per leg with a "Three-team deal" note. The reason is shown in the trade's transaction text. Off gives the classic random trades only; _AI-to-AI Trades Factor_ still sets the overall number of attempts.
- **AI offers to you / Trade Offers** (_AI Trade Offers To You_, options _AI Trade Offers Frequency_ and _AI Trade Offers Expiration_): replaces the stock _Trade Proposals_ page with a _Trade Offers_ inbox, `/l/:lid/trade_offers` (menu _Players → Trade Offers_, trade "More" links; `/l/:lid/trade_proposals` redirects there while the feature is on, and with it off the stock Trade Proposals page and menu item are back and `trade_offers` redirects the other way). AI teams send offers on their own: daily during the regular season (until the trade deadline) and free agency (chance frequency/10 per day), and at the start of the draft lottery, after-draft and re-signing phases (chance frequency/2). About 60% of the time an offer is for something on your trading block (when it has anything), otherwise an unsolicited ask from the team's strategy (contenders want good veterans, rebuilders young players and picks), filled out with `makeItWork` (AI adds only its own assets, pick protections allowed). An offer is only sent if it isn't lopsided against you by the AI's own math from your team's side (value change of at least −2, the point where the trade explanation stops calling a deal "close"; −4 for something on your trading block), so the daily tries go to another team instead (`MIN_USER_DV_UNSOLICITED`, `MIN_USER_DV_TRADING_BLOCK`). Each new offer gets a notification (no inbox message, since unread messages block play). Each offer shows the team, what you give/get, its source (_Trading block_, _Unsolicited_, _You asked_), a value hint from your side (good / roughly fair / favors them) and when it expires; buttons _Accept_ (goes through the normal trade proposal, undoable), _Negotiate_ (loads it on the Trade page, pick conditions kept) and _Decline_ / _×_. _Request offers_ (the old trading block "what would you give") asks every AI team about the selected players/picks and keeps the 3 best answers in the inbox. Offers expire after _Expiration_ days (your games in the regular season, days of free agency), when the phase changes, when the AI team loses a player, or when an asset in it moves; at most 8 are kept, one per team. Stored in the `aiTradeOffers` game attribute (new fields `daysLeft`, `rosterKey`, `source` are optional, so old leagues load as is). No unsolicited offers when AI trades are off (factor 0), in spectator mode, auto play or the no-trades challenge. Code: `trade/aiOffers.ts`, `views/tradeOffers.ts`, `ui/views/TradeOffers.tsx`.
- **Trade Market** (_Trade Market_): _Players → Trade Market_, `/l/:lid/trade_market`, linked from the Trade page, Trade Proposals / Trade Offers and the "trade deadline is coming" notification (a week before the deadline). Lists players each AI team is willing to move (0–100, from strategy, age, contract and role on the team, with reasons) and an asking-price hint relative to the team's own next first round pick.
- **Three-team trades** (_Three-Team Trades_): `/l/:lid/trade_three/:tid1-:tid2`, linked from the Trade page (_3-team trade_). Send any player or pick from any team to any other team. Each AI team must like what it gets (with the same _Why?_ explanations) and the salary cap rules apply to each team's total incoming and outgoing salary; during the season rosters can't go over the maximum. An accepted trade is recorded as one regular trade event per pair of teams that exchanged something, each noting it was part of a three-team trade, so trade summaries and transactions work as usual. Undo is supported. The regular 2-team Trade page is unchanged. AI teams also make rare three-team trades among themselves (see _Need-driven AI-to-AI trades_).

### Draft pick protections and swaps

_Draft Pick Protections & Swaps_ (`featureDraftPickConditions`, all sports; on for new leagues, off for existing ones).

- **Adding a condition:** on the Trade page, every pick in the trade summary has a _+ protection/swap_ link (on the 3-team trade page, once the pick has a destination). Choose:
  - **Top-N protected** (1st round picks only): if the pick lands in the top N of its round, the team that traded it keeps it. _Then next years_ is the protection for each following year (e.g. `8, 5`), and _After that_ is what happens when the last one is protected too: the next year's pick conveys **unprotected**, it **converts to a 2nd round pick** (next year's 2nd rounder of the same team) or it is **extinguished**.
  - **Swap rights only**: the pick stays where it is, the receiving team gets the right to swap its own pick in that draft and round for it, if it's better.
- **Where it shows:** pick descriptions everywhere (trade asset lists, summaries, trading block, proposals, Draft Picks page with a badge; swap rights a team holds are listed on its Draft Picks page), the transaction/news text and Trade Summary page of the trade ("top 10 protected (then top 8, then unprotected)", "the right to swap 2027 1st round picks").
- **Resolution:** when the draft order is set (after the lottery, or at the start of the draft), swaps are executed if the other pick is better, protected picks convey or go back to the original team, and the obligation rolls over to the next season's pick of the same team (or converts/extinguishes). Each outcome is a news event (type `draftPickCondition`) with a notification for your team. If the pick a protection would roll over to was traded away in the meantime, the obligation is extinguished (noted in the event).
- **AI:** conditional picks are valued by their expected value: the chance of each pick slot (projected standings, simulated season odds and lottery odds, as for any pick) is split into conveyed/protected, with a discount for what's owed instead (rollover 60%, unprotected next year 75%, 2nd rounder 12%, extinguished 0). Swap rights are worth E[max(own pick, other pick)] − E[own pick]; a pick carrying someone else's swap right is worth E[min]. When the AI rejects an offer that includes its own 1st round picks, _What would make this deal work?_ first tries protecting them (top 3/5/8/10/14, one rollover year, then unprotected) and proposes the smallest protection that works.
- **AI trades with conditions:** in AI-AI trades (random and need-based), AI trade offers to the user and when it fills out a trade, an AI team may give its own picks with conditions: each step, up to two of its picks also get a variant with a protection drawn from a menu (top 3 → top 3 then unprotected; top 4 → 2nd rounder; top 5 → 5, 3 then unprotected; top 8 → 5 then 2nd rounder; top 10 → 2nd rounder; top 10 → 8 then extinguished; top 14 → 10, 5 then unprotected; only tops below half a round) and, when the partner owns its own pick in that draft, a swap-rights-only variant. They compete with every other asset on value, so they are used when they fit the balance best; rebuilding teams prefer the protected version (counted as if 40% smaller dv). Offers show the condition in the pick description and keep it when you open the offer on the Trade page. The Trade Market's asking price adds how much a top 5 protected first from you counts for compared to an unprotected one. Code: `trade/makeItWork.ts` (`aiPickConditions`, `getConditionVariants`).
- **AI asks for terms on your picks:** when the AI receives picks with conditions from the other team (Trade page _What would make this deal work?_, trading block / AI offers, AI-AI trades), `makeItWork` also tries changing the terms on those picks as candidate assets, valued like any other: when it wants more, loosening a protection the other team added (dropping the last rollover year, falling back to unprotected instead of a 2nd rounder/extinguished, lowering top-N to 8/5/3/1, or removing it); when it's getting more than it needs and the user's side can change, accepting a top 3/5/10 protection on an incoming 1st. The usual forward selection picks the smallest change that balances. The Trade page message says what changed ("They want the top 10 protection on your 2027 1st round pick lowered to top 5.", "...removed.", "They'll accept top 5 protected on ..."), and offers show/keep conditions on your picks (`tradeFor` `userPickConditions`). Only conditions added in the trade can change (existing ones on stored picks can't). Code: `getPickTermsVariants` in `trade/makeItWork.ts`, `getProtectionLoosenings`/`pickConditionChangeText` in `common/draftPickConditions.ts`, `getPickTermsMessages` in `trade/makeItWorkTrade.ts`; tests in `trade/pickTerms.test.ts`.
- **Changing a protection already on a pick:** a pick with a protection from an earlier trade can have that protection lowered or removed when it moves again, if the team holding the protection (the one that keeps the pick when protected) is also in the trade and isn't the one receiving the pick. In practice that's a 3-team trade; in a 2-team trade that team is never a party, so stored protections are only valued, not changed. In a trade it's a condition with `amend: true` (top 0 = removed). Valued with the new protection and the protecting team as fallback owner, applied in `processTrade` (text "protection changed to ..."/"protection removed"), and undo restores the old protection (not once the draft order is set). Validation: `validatePickConditionSpec(spec, dp, n, { participants, toTid })`.
- **3-team "What would make this work?":** button on the 3-team trade page. AI teams that don't like the trade ask for the smallest changes to the terms of picks they receive: loosening protections added in the trade, and loosening stored protections held by your team (not ones held by another AI team, which would lose value it isn't paid for). Greedy, up to 8 steps: a change that makes every AI team accept with the smallest gain, else the smallest change that gets the unhappy teams closer. The page shows "Team: We want the top 10 protection on your 2027 1st round pick lowered to top 5." etc.; a changed stored protection has a _keep existing_ link to undo the ask. Code: `makeItWorkMulti` in `trade/multiTeam.ts` (API `makeItWorkMultiTeamTrade`).
- **Starting protections:** in AI offers to you and random AI-AI trades, a 1st round pick the AI asks for starts with a protection from the AI menu 35% of the time (`withStartingProtections`, `STARTING_PROTECTION_PROB`), so the AI then asks to loosen it or keeps it (the offer text says "your 2027 1st round pick (top 5 protected)").
- **Valuation of what's owed:** the rollover / 2nd round pick owed instead of a protected pick is weighted by the chance it is delivered: 0 if the original team no longer owns it (or it is in the same trade, or already has a condition), 90% if it owns it (it could still trade it later), 90% if it isn't generated yet. Swap rights are discounted 10% for lapse risk (and worth nothing if the swapping team's own pick moves in the same trade); a pick carrying someone else's swap right is valued 90% swapped, 10% as itself. `getFallbackDeliveredProb`, `CONDITION_SURVIVE_PROB` in `ValueChangeCalculator.ts`.
- **Storage:** `draftPicks[].protection = { tid, top, rollover, then }` (tid = team that keeps it if protected) and `draftPicks[].swap = { tid }` (team holding the right), in the league file too (JSON schema updated, no DB migration needed). Pending conditions in a trade are `trade.teams[i].pickConditions`. Code: `common/draftPickConditions.ts` (text/validation), `worker/core/draft/pickConditions.ts` (resolution, called from `genOrder`), `processTrade` (apply/undo), `ValueChangeCalculator` (valuation), `trade/tryProtections.ts` (AI counters).
- **Limits:** one condition per pick; conditions can't be added to a pick that already has one, or once the draft order is set; swap rights themselves can't be re-traded (the pick carrying them can, and the right stays with the team); no "least favorable of" picks.

## Draft and scouting

### Draft Scouting

- **Where:** _Players → Draft → Draft Scouting_ (`/l/:lid/draft_scouting`).
- **College and overseas stats** (_College & Overseas Stats_): the _College stats_ button above each draft class generates college (or overseas pro club) stats and honors for its prospects from a seed (same seed, same result), or regenerates/removes them. They show on the player page with a _College_ or _Overseas_ tag in the stats tables and an _Earlier honors_ box, and are **not** pro stats: they don't count toward experience, career totals, awards, Hall of Fame or player value. The option _Generate Pre-Draft Stats Automatically_ does it for every new draft class (all classes at league creation, each season's new class, fantasy/expansion/custom classes, and imported prospects who have none). _All draft classes_ panel: the same for every upcoming class at once (seed, only prospects without stats or replace everyone's). Class year and career shape follow draft stock (`getClassIndexForStock` in `collegeStats/generate.ts`): age at the draft spans two class years, so a high-stock prospect is a year younger in school than his age says (a 20-year-old lottery pick is an older one-and-done, a 21-year-old one a sophomore), and four-year seniors are mostly lower-ranked prospects. A college season he came back after is held below declare-worthy stock (`STAY_CAP`: class z above 0.55 compressed, the excess becoming extra rating lag), so stats grow across his seasons instead of a dominant freshman staying four years. Usage has diminishing returns above 29% (max 35%) and assists per 40 cap at 9.5. Stored classes are not rewritten; only new generation changes. The draft stock timeline's _Now_ point ranks by true value (the order the AI drafts in, as the Mock Draft does) rather than the fuzzed scouting list, and its random walk tightens toward the draft.
- **Regenerate ratings** (_Ratings Regenerator_): rebuilds prospects into specialized builds or archetypes (Floor General, Stretch Big, Rim Protector, …) without changing overall, potential or height. Scope: whole class, selected prospects, one prospect, or all classes at once (a preview summary per class, one _Undo last apply_ for all of them, and _Restore originals_). Settings include seed, variation, class flavor and strength, builds per class, archetype diversity, specialization and rookie caps, each lockable; per-player reroll and rating locks; preview with diffs; _Apply_, _Undo last apply_ (until reload) and _Restore originals_ (survives reloads). _Save as league default_ keeps the settings for _Re-randomize New Draft Classes_ (option; ratings first, then pre-draft stats; seeded from the league and class year; drafted players are never touched).
- **Class shape** (_Draft Class Shapes_): under each class's year, its shape and a line about it (see below).
- **Scouting system** (_Scouting System_): your scouting budget gives you scouting points every season to spend on individual prospects: assign a scout (1 point) or attend a workout (3 points) in the _Scout report_ column. Each narrows how far off your view of that prospect's ratings can be and gives a scout report with ovr and pot ranges, a confidence and notes. Prospects you don't scout keep the normal rating fuzz.
- **Columns:** _Archetype_ (with the Archetypes switch), _Traits_ (with player traits), badges.

### Draft class shapes

- **Where:** League Extras → _Draft Class Shapes_ (`featureDraftClassShapes`, on for new leagues, off for existing ones). Shown under each class on Draft Scouting and above the Mock Draft.
- **What:** every draft class the game generates from scratch draws a shape from the league and class year, which reshapes the top of the class (the 60 best prospects by value) within realistic bounds: _A typical class_ (16% of classes, no change), _A deep class_ (9%: prospects 6-45 about 2.2 ovr better), _A top-heavy class_ (8%: two or three franchise talents 5 better, prospects up to 35th 2 worse), _A weak class_ (9%: the top 40 2.5 worse), _A generational talent_ (3%: the No. 1 prospect 6.5 better, the next 29 slightly worse), _No clear No. 1_ (7%: the top five pulled halfway to the sixth, the next ten a little better), _A guard-heavy class_ / _A big man class_ (7% each: half of the other prospects rebuilt toward a guard or a big, same ovr, height and weight changed), _A wing class_ (7%: 60% of the guards and bigs rebuilt toward the wing), _An international class_ (6%: 30% of the US-born prospects from overseas instead, a name from that country and a blank college so pre-draft stats are at a pro club), _A college-senior class_ (6%: 40% made seniors at the oldest draft age, 1 ovr more polish), _A high-upside class_ (7%: most a year younger, 1.5 ovr rawer), _A ready-now class_ (7%: a year older, 1.5 ovr more ready). Ages stay within the league's draft ages.
- **When:** a class made from scratch (each season's new class, the top-up to the number of draft classes, every class of a random players league at creation) is marked `p.draftClassShape = "pending"` when it is generated; `processNewDraftClasses` gives it its shape before anything else (so _Re-randomize New Draft Classes_ rebuilds the shaped ratings, which keeps the shaped ovr, and pre-draft stats are made from them), once: the mark becomes the shape's key. With the setting off the mark is just removed. Imported, uploaded, topped-off, real-player and scrub classes are never marked, so never reshaped.
- **Balance:** over how often each shape comes up, the top 60 of a class is as good as before (test: weighted ovr change within 0.35, pot within 0.75; per shape at most 3.5 ovr). Rating inflation population model (`RI_CONFIGS=off,shapes`, 16 seeds, 12 seasons): league mean ovr within +0.35 of the same leagues without shapes every season (12-season average +0.05), pot within -0.3, top-10 ovr 0.3-1.0 lower; forcing one shape on every class moves league ovr about +1.0 (deep), -1.7 (weak), -1.5 (seniors), -0.9 (top-heavy), -0.4 to -0.6 (ready-now, high-upside) and ~0 (generational, guards, international), so the mix leans slightly deflationary. The `ratingInflation` regression test runs with it on (it is a new-league default).
- **Engine:** `common/draftClassShape.ts` (shapes, draw, plan; pure), `worker/core/draft/classShape.ts` (applies a plan: shifts the skill ratings to the new ovr, builds toward a position, ages, origins), tests in `worker/core/draft/classShape.test.ts`.

### College season and March Madness

- **Where:** _Draft Scouting → College/Overseas_ tab (`/l/:lid/college_overseas/:season/:tab`, tabs `standings`, `ap`, `conference`, `selection`, `ncaa`, `nit`, `overseas`), the player page (a _{year} {school}_ box next to _Earlier honors_), Ctrl+K "College/Overseas".
- **What:** a light college season for each draft class's draft year, made together with the class's college stats (the _College stats_ button, the _All draft classes_ panel, and _Generate Pre-Draft Stats Automatically_). Every school in the college list gets a team strength (conference strength + program prestige + the class's prospects on its roster, best one counting most), plays 12 non-conference games and a conference schedule (double round robin, or single round robin plus extra games to 20 for big conferences), game by game from the two strengths (scores and overtimes, no GameSim). Then conference standings, conference tournaments (everyone, top seeds get byes; Ivy top 4; winner gets the automatic bid), the final AP Top 25 (62 voters, before the NCAA tournament), Selection Sunday (32 automatic bids + 36 at-large by the committee score, see below; the last four at-large and four lowest automatic bids play the First Four for two 11 and two 16 seeds; S-curve into East/West/South/Midwest), the full 68-team bracket with scores, Final Four and champion.
- **Prospects:** a prospect at an NCAA school plays his team's games: his draft-year college row has the team's game count with the conference and NCAA tournament games at the end (always played), so totals include them. His player page shows the record, conference finish, AP rank, conference tournament result, _NCAA Tournament: Elite Eight (seed 3), South Region_ and his postseason game log. Honors (in _Earlier honors_): conference regular season / tournament champion, conference tournament MVP and All-Tournament team, NCAA Champion, Final Four Most Outstanding Player, All-Final Four team, regional Most Outstanding Player (when the best player was a prospect).
- **Page:** season selector (draft year: upcoming classes and the last 3 drafts), _Standings_ by conference, _AP Top 25_ (with prospect All-Americans), _Conference Tournaments_ (bracket per conference), _March Madness_ (champion and MOP, Final Four, one region at a time, First Four; columns scroll sideways on a phone), _Overseas_ (the class's prospects at pro clubs abroad or in the G League with league, per game stats and honors). Prospect names link to player pages and are shown under their team in brackets and tables.
- **Weekly AP poll** (_AP Top 25_ tab): 19 polls, preseason (reputation: program, prospects, a look at practice, some hype), one after each of the 17 regular season weeks (non-conference games in weeks 1-6, conference play in weeks 7-17) and the final one. The same 62 voters all year, each with a lasting opinion of every team; a team that lost all its games in a week is not moved up for it, one that won them all is not moved down. The page shows each poll with the move from the previous one, first-place votes, others receiving votes, teams that dropped out, the week's biggest risers and fallers, weeks at No. 1, and a grid of every ranked team's rank in every poll. Engine: `common/collegeStats/ncaaPolls.ts` (own random stream).
- **NET and the bubble** (_Selection_ tab): a NET-style ranking computed from results on Selection Sunday (capped margin and wins, both adjusted for schedule and site), strength of schedule rank, records by quadrant (Quadrant 1 = home vs NET top 30, neutral top 50, away top 75...) and road record. The committee score that picks and seeds the at-large teams reads SRS, the NET, the record, Quadrant 1/2 wins, Quadrant 3/4 losses and road wins. The tab lists the last four byes, last four in (the First Four at-large teams), first four out, next four out, notable snubs with the reason (AP ranked, NET top 40, regular season champion, 26 wins...) and bid thieves (conference tournament winners that would not have made it, from a league that also got an at-large team). Engine: `common/collegeStats/ncaaSelection.ts`.
- **NIT** (_NIT_ tab): the 32 best teams left out; regular season conference champions that lost their conference tournament and missed the NCAA field get automatic bids. Four brackets of eight (seeds 1-8), better seed at home until the semifinals, full bracket and champion. Prospects on NIT teams play the games: they are in the team's record, at the end of his draft-year stat line, in his postseason game log and a _NIT_ split, his page shows _NIT: Semifinals (seed 3)_, and honors are _NIT Champion_, _NIT Most Outstanding Player_ and _NIT All-Tournament Team_.
- **Season storylines:** each class's season draws a shape from its seed, and maybe a scoring environment, which bend what the season is simulated with. Version 3 (classes made now) draws from 20 shapes; version 2 classes keep the first seven with their old weights (a test pins whole version 2 seasons against hashes). The original seven: _a balanced year_, _a dominant favorite_ (the best team pulls 3+ points clear), _a wide-open year_ (the top of the country squeezed together, more swing in a game), _the year of the mid-major_ (non-power leagues better, six of their best teams much better), _a down year for the blue bloods_ (half of the 14 biggest programs 4-7 points worse), _one loaded conference_ (every team of one power league better), _chalk all the way_ (less swing in a game); _a scoring explosion_ or _a defensive slog_ (8 points a game more or fewer). A box at the top of the page has the headline and a written summary (whether the shape held, champion and Final Four, preseason No. 1 and weeks on top, the Cinderella, a 16 over a 1, unbeaten teams, bids by conference, first teams out, bid thieves, NIT champion, scoring). Version 3 adds: _two juggernauts_ (the two best teams 3+ points clear of the third: did they meet in the final?), _the year of the freshman_ / _a veterans' year_ / _a guards' game_ / _the year of the big man_ (prospects of that kind, by age in the draft year or position, add 35-45% more to their teams and the others 15-20% less; guards' years score 3 more points, big men's 3 fewer), _a Cinderella run_ (once the field is set, one 10-12 seed, from outside the power leagues when there is one, plays 10 points better in the tournament), _a wild first weekend_ (30% more swing in a game in the First Four and the first two rounds), _parity in the power conferences_ (power-league teams squeezed 40% toward their average), _a fallen powerhouse_ (one of the six biggest programs 8-11 points worse), _a conference down year_ (every team of one power league 3 worse), _the transfer carousel_ (every team ±2.6 points that the preseason poll does not know about), _a great team stumbles_ (the best team 4.5+ clear, 4.5 worse from the Elite Eight on), _pace and space_ (6 more points a game, more swing; never with a defensive slog). Each has its own summary sentence (two wordings for most, picked from the season). Engine: `common/collegeStats/ncaaStoryline.ts`. Long run over 2500 version 3 seasons: 1 seeds win the title 58% of the time (36% in wide-open years, 41% with parity in the power conferences, 52% with a Cinderella run, 58% in a balanced one, 66-68% with a dominant favorite, two juggernauts or chalk), a 16 beats a 1 in 0.9% of those games (2.7-2.8% in parity and conference-down years, 1.6% on a wild first weekend, none in chalk or freshman years), a team is unbeaten on Selection Sunday in 9% of seasons (17% with a fallen powerhouse, 15% when a great team stumbles, 3-4% in pace-and-space, big men's and guards' years), 1.35 double-digit seeds reach the Sweet 16 a year (2.1 with power-conference parity, 1.6-1.7 with a Cinderella run, a wild first weekend or pace and space; the Cinderella run's own team gets there about a third of the time), points a game 71.0 (74.7 pace and space, 72.1 guards, 69.5 big men). The test `ncaaExtras.test.ts` checks the long run over 640 seasons.
- **Versions:** `p.collegeSeason.v` is the version of the simulation the class was made with (3 now; missing = 1). Version 3 classes also store the prospect's position (`p.collegeSeason.pos`), so a guards' or big men's year is rebuilt the same way after his ratings change. A version 1 class (made before the weekly polls, the NIT and the storylines) is rebuilt playing every game exactly as it was played then, so its champion, records, final AP poll, bracket and prospects' lines do not change (a test pins this against hashes of the old output). It still gets the weekly polls, the NET, the bubble (in the order its field was really picked: SRS and record), a written summary and an NIT bracket, but its NIT games are not counted in records or prospects' stats (the tab says so), and its shape is always _a balanced year_. Prospects added later to such a class (only missing) keep it version 1.
- **Cache:** the rebuilt season is kept per class (last 8, keyed by league, draft year, seed, version and every prospect's school and boost), so the page and player pages do not replay it on every load (about 40 ms to build).
- **Storage:** no new store. Each prospect at an NCAA school gets `p.collegeSeason = { season, seed, school, boost, summary, v }`; the season is rebuilt exactly from the class's seed and every prospect's school and boost (`getCollegeSeason` in `worker/core/draft/collegeSeason.ts`), deterministic per seed. Generating stats for only the prospects missing them keeps the class's existing season (newcomers join with boost 0). Removing a class's college stats removes it. Engine: `common/collegeStats/ncaa.ts` (tests in `ncaa.test.ts`), stats integration in `common/collegeStats/generate.ts` (`ncaaSeason` option) and `season.ts` (`teamGames`/`postseasonGames`).

### Prospect careers: transfers, redshirts, recruiting, unusual prospects

Part of _College & Overseas Stats_ (no toggle of its own): everything here is made when a class's college stats are generated, and is biography built around the ratings a prospect already has. Nothing reads back into ratings, age, value or how draft classes are generated for the pro game.

- **Where:** the player's _College/Overseas_ page (`/l/:lid/player_pre_draft/:pid`): a story line under the cards, _Scouting report_, _Teams_ (class year, notes), _Stats_, _Recruiting_, _Draft stock_.
- **Multi-school careers** (`common/collegeStats/career.ts`): a career plan is drawn per prospect from his own stream (seed, draft year, pid), separate from his stats stream, so a prospect with a plain career gets the same seasons as before. The draft-year school is always his own (the one tied to the simulated college season); earlier years can be elsewhere.
  - _Transfers_ happen between seasons, never during one (one school per season): up-transfers (a breakout at a smaller school, then a bigger program), down-transfers (buried on a big program's bench, then real minutes) and lateral ones. About 13% of sophomores, 25% of juniors and 34% of seniors at NCAA schools have transferred; a few seniors twice.
  - _Redshirt_ (about 6-11% of multi-year players, more for lesser prospects): his first year on campus with no games (no stats row; listed in _Teams_). It takes the place of a season, since his age is fixed: a redshirt junior (_RS Jr._) is 22. A 23-year-old senior usually has a redshirt year as his fifth year.
  - _Medical redshirt_ (about 4% of juniors and seniors): a season that ended after 3-9 games and did not count against his eligibility.
  - _Junior college_ (about 4-9% of juniors and seniors, more for lesser prospects): one or two NJCAA seasons (inflated numbers against weak competition, _NJCAA All-American_ / _All-Region_ honors) before a Division I school.
  - Class years (_Fr._, _RS So._ ...) are eligibility years. Honors, coaches and team records follow the school of each season.
- **Unusual prospects:** each prospect has a small seeded chance (about 8-10% of a class end up with one) of a story that fits what he already is: _five-star bust_ (a below-average prospect in his class: a top-25 recruit and lottery projection on arrival, fewer minutes every year), _unranked riser_ (a top prospect nobody ranked: bench minutes and often a small school or junior college early), _late-blooming senior_ (barely played until his last season), _7'3"+ project_ (from his listed height: raw, limited minutes), _undersized scorer from a small school_ (6'1" or under at a low-major: carries the offense), _older international_ (22+, a pro abroad since 17 or 18, up to six seasons), _reclassified freshman_ (enrolled a year early), _injury-shortened season_ (his draft-year season ends after 5-15 games; with the college season on he misses the postseason). Minutes, usage, the draft stock timeline and the recruiting rank reflect it, and the page says it in a line.
- **Recruiting:** for prospects with a US high school path (an NCAA or junior college first stop): stars, national and position rank, composite rating (a fixed function of the rank that agrees with the stars), the number of offers and the programs worth naming, finalists, early (November) or late (April) signing, and high school all-star selections (generic names: _High School All-American Game_, _National Senior All-Star Classic_, _Prep Hoops Summit_, _State Player of the Year_). Ranks are against the rest of his high school class, which is spread over several draft classes, so no two players of a class share a national rank or a rank at their position (`worker/core/draft/recruiting.ts`, `resolveClassRanks` in `profile.ts`). The rank is set once, when his stats are generated, and stored; players ranked later fit around it. Offers, finalists and the rest are derived from the rank and the player (not stored), so they also appear for older classes.
- **Scouting report:** strengths, weaknesses and a projection (`common/collegeStats/scoutingReport.ts`), written only from what the user can already see: draft-year ratings with scouting fuzz applied (never true ratings; none at all with the hidden ratings challenge, when the report is written from production alone), the archetype label Draft Scouting shows, height, pre-draft production and where the user's board has him (or where he went). Player traits are never used. Appears for old classes too.
- **Storage:** `p.preDraftCareer = { years: [{ season, school, level, cls, status?, move? }], story?, hsClass?, recruit?: { rank, posRank } }` on prospects whose stats were generated with the career model; removed with the class's college stats. Stats rows are unchanged (one row per season played, `teamName` = that season's school). **Classes generated before this keep their stored seasons**: the page falls back to what the rows say (one class year per row, recruiting rank derived as before and only bumped to the next free rank on a collision within the high school class). A stored career that no longer matches the rows (edited or re-imported stats) is ignored.
- **Engine hooks:** `season.ts` `mpgShift`, `usageShift`, `gamesCap` (all optional; nothing changes without them). Tests: `career.test.ts`, `profile.test.ts`, `scoutingReport.test.ts`, `worker/core/draft/recruiting.test.ts`.

### Draft board and AI drafting

- **Draft Board** (_Draft Board_): `/l/:lid/draft_board[/:season]`, linked from Draft Scouting and the Draft page. Rank your prospects, give them tiers and notes next to their pre-draft stats, builds and scout reports. Option _Auto Draft From My Board_: when auto drafting for you, the top-ranked available prospect on your board is picked. The Draft page also has a _Draft-day trades & team boards_ window (trades through the trade API, each AI team's needs and board).
- **AI drafts by need** (_AI Drafts by Need_, basketball): AI picks get a small need (guard, wing, big) and strategy (contenders want players who are ready, rebuilding teams want ceiling) adjustment on top of value, at most about 2 value points (`draftNeeds.ts`; value still decides most picks). Off: the old pure-value drafting.
- **Mock draft** (_Mock Draft_, basketball): `/l/:lid/mock_draft`, a tab of Draft Scouting. A two-round mock draft of the current class (until its draft is over; during the draft, the remaining picks). Each team picks the way the AI does in `runPicks.ts`: value plus the need/strategy adjustment (when _AI Drafts by Need_ is on) and the player-traits nudge (when traits are on), with the same weighted random choice. The order is the league's draft order with traded picks once the lottery is done, otherwise one simulated lottery (like the projected Draft Lottery page). Pick protections and swaps are resolved on that order as a dry run with the same code as the real draft (`resolvePickConditionsPure` on copies: no saves, no news), and each affected pick says what happened (swapped, protected and stays, conveyed). Each pick shows why (best available, fills a need, ceiling or ready-now, traits, reach or steal against your scouting list); _Rerun_ draws again; your picks are highlighted. Pro projections: 120 careers per prospect run with the game's own development (`developSeasonSync`) from his ratings as your scouts see them, with a simple out-of-the-league rule, giving the median and 10th-90th percentile peak ovr and star (65+) / starter (58+) / bust (under 50 or gone within 4 seasons) odds, ported from the Draft Workshop. Cached per league, season and ratings in the worker; shown on the Mock Draft tab and as a _Pro projection_ section on a prospect's player page (`mockDraft.ts`, `proProjection.ts`, `mockDraftData.ts`).

### Customize Player: Regenerate build

- **Where:** a player page → _Edit_ (`/l/:lid/customize_player/:pid`), _Regenerate build_ button (opens a dialog).
- **What:** the same build engine for one existing player: preview, pin ratings, reroll; keeps ovr, pot and height.

## Coaching staff

- **Where:** Team menu → _Coaching Staff_ (`/l/:lid/staff`, `/l/:lid/staff/:team`), League menu → _Coaches_ (`/l/:lid/coaches[/:season]`: head coaches, the season's coaching carousel, Coach of the Year history), and a page per coach (`/l/:lid/coach/:cid`). Team Finances links to the staff instead of offering the coaching slider.
- **What:** every team has a head coach and three assistants (player development, offense, defense) with ratings (development, offense, defense, motivation), a style (pace, threes, defense, rotation, each -1 to 1), age and a contract. Salaries are paid as coaching expenses (not against the salary cap). The staff's development score is turned into an equivalent coaching budget level, so it replaces the coaching budget's effect on progs, normalized by the league's average staff each time levels are synced, so the league-wide development effect stays centered like default AI coaching budgets while the coach pool's ratings drift over the decades (see `staff.test.ts` and [rating-inflation.md](rating-inflation.md)). After the playoffs each season: records are written to each coach (a coach hired or fired during the season gets only the games he was in charge of), Coach of the Year is awarded, coaches age/improve/retire, contracts expire, AI teams fire (losing head coaches especially) and hire from the pool (bigger markets pay more). Your expiring coaches leave unless you _Extend_ them; firing pays half the remaining contract as a buyout. Any vacancy still open in the preseason is filled automatically.
- **Setting:** `coachingStaff` (basketball only). On by default for new leagues; existing leagues (DB version 76 migration) and league files from before version 76 keep the slider until it's turned on, which generates staffs.
- **Storage:** `coaches` object store (key `cid`, index `tid`), included in league export under _All team data_.
- **For other features:** `src/worker/core/staff/data.ts` has `getTeamCoachStyle(tid)` (for team strategy / game sim later), `getCoachingCarousel(season)`, `getHeadCoachForSeason(tid, season)` and `getCoachAwards(type)`.
- **Known limits:** no in-game effects yet (style is exposed only). Scouts and trainers are not modeled. With the budget disabled, every team gets the average development effect, as with the slider.

## Known limits (all features)

- Basketball only unless a section says otherwise; the other sports hide the menu items and links.
- The Wrapped, Storylines and Timeline pages share a whole-history snapshot that takes a while the first time in a big league.
- The league-wide averages with player traits, the possession model or injury depth on stay about the same as with them off, but individual games and seasons are of course different; use the switches (off) to replay the old behaviour.
- Existing leagues keep playing as before until the game-affecting switches (possession model, traits, injury depth, contracts, trades, drafting, coaching staff) are turned on in League Extras. Games already played replay unchanged.
- Draft board and scouting need prospects: the Draft Board is empty in a league without upcoming classes.

## Performance

Wrapped and Storylines read the whole league into a snapshot. Converted pieces that can't change any more (retired players, finished seasons' box scores and team seasons) are cached in a separate IndexedDB database (`wrapped-cache`), versioned by the converter code and invalidated through the league's change log, so later sessions only read what changed. Idle snapshots are evicted from memory. `tools/perf/wrapped/` holds the Playwright benchmark scripts (see the header of `bench.cjs`).
