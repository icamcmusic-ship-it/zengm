# Native features

This fork adds a set of pages, tools and game-sim options to Basketball GM. The first group (Newspaper, Wrapped, Storylines, Games to Watch, achievements, Trade Grader, Timeline) used to live in the separate League Explorer app: they are built from the league's own records and run locally in the game's worker. The rest are game features (play-by-play options, a realistic possession model, player traits, injury depth, contracts, trades, drafting, coaching staff, ...).

Most of it is **basketball only**: in Football, Hockey and Baseball GM the menu items and links are hidden and the routes show a short "only available for basketball" message. The exceptions, which work in every sport, are the contract features and the trade features (the code is shared), the Draft Board and the Scouting System.

`:lid` below is the league id, as in `/l/1/...`.

## Where the pages live

Pages that belong with an original BBGM page are tabs of that page: a tab bar at the top of the page (it scrolls sideways on a phone) switches between them. Each tab keeps its own URL, which is the page's old URL, so old links, bookmarks and the command palette (Ctrl+K) land on the right tab. Tabs of a League Extras feature that is off are hidden, and the side menu highlights the host page on any of its tabs. The tab list is `src/ui/util/pageTabs.ts`; `src/ui/util/consolidatedPages.ts` lists the pages kept out of the side menu.

| Transactions     | Transactions, Trade Grader                      |

## League extras (feature toggles)

- **Where:** Tools → _League Extras_ (`/l/:lid/league_extras`), and the _League extras_ category at the bottom of League Settings (and of the New League form). Same settings in both places.
- **What:** an on/off switch for every feature above, plus the options of some. A feature that is off disappears from the menus, the command palette, _More_ links, history/team/player page links and the dashboard, its pages show "turned off" if opened directly, and its background work stops (no hype computed, no achievement checks, no season odds simulations, no AI offers, no archetype updates, ...).
- **Options** (shown with their feature): hype _on Dashboard_ / _on Schedules and Box Scores_; achievement _Notifications_ / _on Dashboard_; box score play-by-play _Always show_ or _Show on button press_; _Games to Save Play-by-Play For_ (all games, my team's games, none); _Holdout Frequency_; _AI Trade Offers Frequency_ and _Expiration_; _Generate Pre-Draft Stats Automatically_; _Re-randomize New Draft Classes_; _Auto Draft From My Board_; unretirement chance, minimum age and ovr boost.
- **Sports:** basketball-only switches are hidden in the other sports (Extra Frivolities, the contract features and the trade features show there).

### Adding a toggle (for developers)

The registry is `common/nativeFeatures.ts` (root `common/`, so the build tools can use it for the league file schema); game code imports it through `src/common/nativeFeatures.ts`. Add **one entry** to `NATIVE_FEATURES`:

```ts
{
	id: "myFeature", // used in code
	key: "featureMyFeature", // game attribute holding the switch
	name: "My Feature",
	description: "One line for the settings form.",
	default: true, // existing leagues (missing attribute)
	defaultNewLeague: true, // optional, if new leagues should differ from existing ones
	sports: BBGM, // omit for every sport
	existing: true, // optional: the key is a game attribute declared elsewhere (type, default, schema), so only its form entry comes from here
	options: [ // optional
		{ key: "myFeatureSomething", name: "…", description: "…", type: "bool" | "int" | "float" | "string", default: …, min?, max?, values?: [{ key, value }] /* for string */, decoration?: "percent", existing?: true },
	],
},
```

That entry alone gives: the `GameAttributesLeague` types, `defaultGameAttributes`, the new league defaults, the league file JSON schema, the settings form entries (League extras category and page), the settings view values, the UI sync (local state) and the sport filtering. For an `existing` key you still declare it in `types.ts`/`defaultGameAttributes.ts`, and add its explicit new league default in `worker/views/newLeague.ts` (`getDefaultSettings`). Then gate the feature's code with:

- Worker: `featureOn("myFeature")`, `featureOption("myFeatureSomething")`, and for a page's view `const off = featureOffError("myFeature"); if (off) return off;` (`src/worker/util/nativeFeatures.ts`).
- UI: `useFeatureOn("myFeature")` / `useFeatureOption(...)` in components, `isFeatureOn(...)` in plain functions (`src/ui/util/nativeFeatures.ts`); menu items take `feature: "myFeature"`; for links to the feature's pages add the URL to `featureForUrl` so `MoreLinks` and `FeatureLinks` drop them automatically.

Tests in `src/common/nativeFeatures.test.ts` check that every key has a default and is synced to the UI.

## Pages built from the league's records

### Newspaper

- **Where:** League menu → _Newspaper_, `/l/:lid/newspaper`, `/l/:lid/newspaper/:team/:season` (`all` or a team like `ATL_0`). Also linked from the dashboard ("From the records"), the team pages' _More_ links (team edition), League → History and each season row of Team History.
- **What:** a front page plus sections (Playoffs, Awards, Teams, Players, Features, Transactions, By the numbers, Opinion, Colour & letters) written from the season's results, awards, transactions and box scores. During a season it reports "so far"; after the playoffs it becomes the final edition. A team edition focuses on one franchise. Back issues link to earlier seasons. _Print edition_ gives a print-friendly layout.
- **Known limits:** pull quotes and letters marked _Colour_ are invented voices (the numbers are real). Player photos load lazily as you scroll. Very old seasons with deleted box scores get fewer game stories.

### Wrapped

- **Where:** League menu → _Wrapped_, `/l/:lid/wrapped` (chooser), `/l/:lid/wrapped/season/:season`, `/l/:lid/wrapped/team/:season/:team`, `/l/:lid/wrapped/player/:season/:pid`, `/l/:lid/wrapped/all`, and `/l/:lid/wrapped/compare` (two players, teams or seasons side by side). Linked from team, player and history pages.
- **What:** a tap-through story deck (9:16 cards) of a season, a team's year, a player's year or the whole league's history. Arrow keys, the on-card buttons, tapping the left/right of the card or swiping move between slides. Each slide can be saved or copied as a 1080×1920 PNG.
- **Deck settings** (gear icon on the card, remembered per browser): number of slides, autoplay, **quiz** (a few "who led the league in…" questions mixed into the deck, with a score slide; on by default) and **no spoilers** (hides results that would give away the season's outcome).
- **Compare:** a scoreboard of the main numbers (the better value is bold with ▸), the topics both have with a winner per topic, and the slides only one side has.
- **Known limits:** the first visit to a big league builds a snapshot of the whole history, which can take a while (a progress placeholder shows; later visits use a cache, see _Performance_). Autoplay waits on an unanswered quiz question. A season that isn't over yet gets a "so far" deck without awards or playoffs.

### Storylines

- **Where:** League menu → _Storylines_, `/l/:lid/storylines`, `/l/:lid/storylines/team/:team[/:season]`, `/l/:lid/storylines/player/:pid`, `/l/:lid/storylines/all/all/:season`. _Wrapped_ and _Storylines_ buttons are on each player page; team pages and history pages link here too.
- **What:** story cards found in the league's history (Cinderella runs, upsets, droughts, dynasties, big triple-doubles, ageless wonders, ring chasers, homecomings, stacked draft classes and more), each with a _Why this story?_ button that shows the numbers behind it. The _Threads_ tab groups stories that belong together. Filter by season, kind and order, or search.
- **Known limits:** shares the Wrapped snapshot, so the first visit to a big league can take a while. Stories need history: a new league has only a handful.

### Games to Watch (hype)

- **Where:** League menu → _Games to Watch_, `/l/:lid/hype`; a _Games to Watch_ card on the league dashboard; a hype badge and reasons under games on Schedule and Daily Schedule; a hype card above box scores.
- **What:** a 0–100 must-watch score for upcoming games from what's known before tip-off, and for finished games a 0–100 game rating ("How it played out") plus a verdict comparing the two ("Did it live up to it?"). _Record chases_ lists players close to league or franchise records.
- **Pre-game signals** (each a listed reason with its points, up or down): playoff round and series state (elimination, winner takes all), play-in; two winning teams, marquee matchups (two of the league's top four), top-seed battles, playoff-line races late in the season, teams that can close in on a spot or are on the brink of elimination, tank races; rivalries (past playoff series, last year's knockout), division rivals; star power (stars, a superstar, stars on both sides); career milestones, record chases, heaters, revenge games, rookie duels, streaks, opening night. Lowering it: two losing teams, stars out injured, back-to-backs, late-season games where both teams' playoff fates are settled.
- **Game rating signals:** final margin (close up, blowouts and games over after three down), overtimes, lead changes and ties at period breaks, comebacks (bigger later), clutch plays (game-winners, buzzer-beaters, shots to force overtime, defensive game-winners if the sim records them), individual lines scored by **rarity** against the distribution of single-game lines (points, rebounds, assists, steals, blocks, threes and game score, scaled to the season's scoring environment, so a line is judged against its era) plus feats (triple- and quadruple-doubles, 5x5s, 20/20s, 15+ assists with few turnovers, 28+ points on 70% true shooting, perfect shooting, the season's best single game), star duels, shootouts, team season highs (points, threes), upsets (records, seeds, team ratings), streaks ended, milestones reached and records broken, playoff context (round, series won, winner takes all, title clinched; damped in routs), and what was at stake going in. Lowering it: blowouts, ugly shooting, sloppy (turnover-heavy) and low-scoring games, two losing teams. Works from box scores alone (no play-by-play); missing shooting or turnover numbers just skip those signals.
- **Scale:** raw points map to 0–100 through percentile knots measured on simulated games, so both scores spread over the range: about half of all games under 50, one in twenty 85 or more, one in twenty 20 or less (playoff games sit higher). The tables are `src/common/hype/calibration.generated.ts`, made by `tools/hypeCalibration/calibrate.ts` from seasons simmed in node by `src/worker/util/hypeCalibration.test.ts` (off unless `HYPE_CAL_OUT` is set; see the file headers); `bbgm.hypeCalibrationDump(season)` in the worker console dumps a real league's season in the same format.
- **Verdict:** _Better than billed_ when the rating beat the hype by 20+, _Didn't live up to it_ when it fell 20+ short, else _Lived up_ (rating 50+) or _A quiet one_; the text gives both numbers and the biggest reasons (plus what happened to the pre-game story lines).
- **Known limits:** record chases need a few seasons of history. Schedule badges are only computed for the next 8 games. Career highs are not detected (box scores of whole careers are not kept); late-game flow is read from period scores and clutch plays, not play-by-play. The calibration leagues are random-players leagues simmed with the default settings.

### League achievements

- **Where:** League menu → _League achievements_, `/l/:lid/league_achievements`; a _Recent achievements_ card on the dashboard; unlocks are announced as notifications.
- **Rarity:** measured on simulated random-players BBGM leagues, not on real NBA history (BBGM sims are far more generous): common more than 0.6 times a season, rare 0.15–0.6, legendary 0.025–0.15, impossible rarer. No tier that any calibration league unlocked in its first 5 seasons is impossible. The data is `src/common/leagueAchievements/calibration.generated.ts`; regenerate it with `tools/leagueAchievementsCalibration/`: `src/worker/util/leagueAchievementsCalibration.test.ts` sims a league headlessly in Node (fake-indexeddb, skipped unless `LA_CALIBRATE_OUT` is set; see its header) and records the tally every season (`sim.cjs` does the same in a headless browser against the dev server), and `calibrate.ts` turns the outputs into bands.
- **Saved state:** which tiers were already announced, and the log, are kept in the league (the `leagueAchievements` game attribute), so exporting and importing a league carries them. Older versions kept them in a separate `league-achievements` database: it is read once per league and moved in.

### Trade grader

- **Where:** League menu → _Trade Grader_, `/l/:lid/trade_grader[/:tab/:team/:season/:ws]`; grades also show on Trade Summary and the transactions list.
- **What:** each side of every trade graded by the win shares what it received produced for it. A toggle counts **regular season + playoffs** (default, `ws` = `all`) or **regular season only** (`rs`); Trade Summary and the grades on the Transactions list follow the last choice made on the grader (per browser). Each side notes the titles its team won with a player it received playing for it in those playoffs.

### Contract value

League menu → _Contract Value_: a value index, bargains and albatrosses, and the value index shown on player salaries.

### League timeline

- **Where:** League menu → _Timeline_, `/l/:lid/timeline[/:from[/:to]]`; linked from the dashboard ("From the records") and from each season row of League → History.
- **What:** season by season (newest first): champions (with the finals result), MVPs and Finals MVPs, the newspaper's front page lead, the top 3 storylines, league achievements unlocked, records (best/worst regular season record in league history so far, single-game scoring records), the 3 biggest trades (by the trade event's importance) and comebacks. Every entry links to its source page (playoffs, player, newspaper edition, storylines season, achievement, box score, trade summary). Filters: season range (navigates), kinds (remembered per browser), team and a text search.
- **Known limits:** headlines are computed for at most the 25 latest seasons of the range (finished seasons are cached in memory). Entries from Newspaper, Storylines and League Achievements are left out while those features are off (the page says which). Storylines need the Wrapped snapshot: on a first visit they appear when it's ready. Achievements come from the saved unlock log, so ones unlocked before achievements were tracked in the league don't show.

### Unretirements

- **What:** the old console script `tools/console-scripts/unretire.js`, built in (off by default). Once a season, when free agency starts, with the chosen chance (default 10%), one random retired player who retired at the minimum age or older (default 35) comes back as a free agent with a fresh ratings row for the season, boosted by a random 3-6 ovr (settings) by raising his non-height ratings one point at a time, favouring his strengths. Dead players, and anyone who already came back (including through the script), are skipped. A news event ("… has come out of retirement and is now a free agent") is logged and shown, and the comeback appears on the timeline.
- **Code:** `src/worker/core/phase/unretire.ts`, called from `phase/finalize.ts`.

### Extra frivolities

Redraft, Draft Pick Value, Jersey Numbers by Team, Family Trees, League Economics and Home Court (the ones available in the sport). One switch hides the lot.

### Face style gallery and extra face parts

- **Where:** Tools → _Face Style Gallery_ (`/face_style_gallery`, in and outside a league; all sports).
- **What:** every option of a face feature (hair, hairBg, eye, eyebrow, facial hair, accessories, glasses, head, mouth, nose) drawn on four sample faces with different skin and hair colours, to check how parts overlap. _New sample faces_ rerolls the faces.
- **Extra parts:** `src/common/faceParts.ts` wraps facesjs so the fork can register its own SVG part options. Registration is append-only (ids start with `fork-`, a facesjs id or an already registered id is never replaced), so existing faces render exactly as before, and facesjs' `generate()` never picks a fork part (its random picks filter by a gender table internal to facesjs). Three example hair styles (`fork-flat-top`, `fork-mohawk`, `fork-buzz`) are included.
- **Setting:** _Use the fork's extra face parts in this browser_ on the gallery page (browser-local, `localStorage.forkFaceParts`, default off). On, the example parts are registered at startup, so a face that names one draws it; off, such a face draws no hair there. The gallery itself registers them while open, to show them.
- **Licence:** facesjs is Apache-2.0 (`node_modules/facesjs/LICENSE`); the fork's parts are new SVG, not copies of facesjs art.
- **Known limits:** groundwork only: nothing assigns fork parts to players yet (no generation, no face editor support; the external face editor doesn't know them). With a hat accessory facesjs hides hair ids it doesn't know, fork ones included. Only the UI registers parts (the worker doesn't render faces).

## Game simulation

### Play-by-play

- **Flavor (live game view):** varied, ratings-aware wording for every play (shot types, passes, fouls with personal and team foul counts, bonus situations, runs, milestones, quarter summaries). It only changes the text: game results are identical with or without it (covered by `outcomeInvariance.test.ts`). Elam ending events and shootout lines keep the original wording; clock phrases follow the league's quarter length and number of periods, and shootout lines are seeded like the rest, so a replay reads the same.
- **Clutch plays:** game-winning, game-tying and overtime-forcing shots (box score notes, news feed, player events) use the flavor wording too ("X buries a step-back three, set up by Y, with 2.1 seconds left to win it"), with the shot type, assister and defender taken from the sim's own clutch-play record (`meta`), so it works with play-by-play logging off; seeded by gid and the play's index (`src/common/pbpFlavor/clutch.ts`). **Game-saving defensive plays** are recorded the same way: a block, steal or forced turnover (credited to the man guarding the ball handler) in the last 10 seconds of the 4th quarter or overtime, with the defense tied or ahead by no more than the offense could have scored on that play (2, or 3 for a three-point try or a turnover), kept only if that team wins in that period and the offense never scores again. Not under Elam endings. The sim has no charges/offensive fouls, so none are recorded. About 70-90 shots and 35 defensive plays per 1,230-game season (`clutchFeats.test.ts`); no random numbers are used.
- **Live play-by-play** (`pbpLiveGame`): show the feed when watching a game live. When off, the score, clock and box score still update.
- **Box score play-by-play** (`featurePbpBoxScore`, option `pbpBoxScore`): _Always show_ the play-by-play as a box score tab, or _Show on button press_ (the text is only made after pressing _Show play-by-play_, remembered per game for the browser session). When the switch is off, box scores have no play-by-play at all.
- **Save play-by-play** (`storePlayByPlay`, option `pbpStore`): which games keep their play-by-play with the box score: _All games_, _My team's games only_, _None_. About 7 KB per game, deleted with the box score. `storePlayByPlay` off (the old on/off setting) still means _None_ and is kept in step with the scope by `setGameAttributes`. Helpers and tests: `src/common/pbpSettings.ts`.
- **The sim never depends on any of it:** the same seeded game gives the same box score with logging off, stored and live (tests in `outcomeInvariance.test.ts` and `playerTraitsSim.test.ts`).
- **Known limits:** the wording assumes 12-minute quarters for some clock-based phrases.

### Game simulation options

- **Technical & flagrant fouls** (`technicalFouls`): rare technical fouls (1 FT, possession unchanged), flagrant fouls (2 FTs and the ball) and ejections.

### Realistic possession model

`realisticPossessions`. Possessions play out like in the NBA: a 24-second shot clock (14 after an offensive rebound), fast breaks and half-court possessions, late-clock shots and shot-clock violations, holding for the last shot, 2-for-1s, and intentional fouling late in games. Box score averages stay about the same (`possessionMetrics.ts` prints a before/after table: `POSS_METRICS=1`). Code: `src/worker/core/GameSim.basketball/possessionModel.ts`. Every random number it draws is drawn only when the setting is on. Player traits feed its shot discipline and consistency hooks (see below).

### Player traits

- **Where:** player pages (Traits section), Draft Scouting (Traits column), Advanced Player Search (Traits filters and columns), Customize Player in God Mode (trait sliders), and the game sim.
- **What:** thirteen 0-100 traits (clutch, consistency, durability, shot discipline, off-ball movement, screens, hustle, foul discipline, recovery, handle under pressure, late-game IQ, leadership, veteran savvy) derived from ratings, age, experience and a stored per-player random component. Prospects' traits are estimates that sharpen with scouting and with seasons played. In the game sim they nudge shots, turnovers, fouls, steals, free throws, fatigue recovery, team synergy, end-of-game decisions and injuries by small amounts (veteran savvy also mentors young teammates: a zero-sum preseason progression bonus of up to +-0.5 ovr) that average out league-wide (10,000-game table in `docs/player-traits.md`). With the setting off the sim is byte-for-byte what it was.
- **AI uses traits:** with the setting on, AI teams multiply a player's (positive) value by a bounded trait factor (1 ± 7% at the extremes, typically ±3%) in trade valuation (`ValueChangeCalculator`), free agent signing order (`freeAgents/autoSign.ts`), contract demands (`normalizeContractDemands.ts`, half strength) and the draft (`runPicks.ts`, a nudge capped at ±1.5 value points). Only the part of each trait not already explained by ratings counts, so the AI doesn't pay twice for ratings; durability (injury proneness / iron man) weighs most, then veteran savvy, leadership, clutch, shot discipline and the rest. Veteran savvy is worth 1.5x to contenders and more to teams with young players to mentor, half for young players themselves. AI teams know pros' true traits; draft prospects are read through the same fixed scouting error the user sees (hidden traits count half). The same factor applies to players coming in and going out, so it can't be arbitraged. Measured: factor averages 1.002 over a random league (contract factor 1.001), so value and pay levels don't drift. With the setting off it is exactly 1. Code: `common/playerTraits/aiValue.ts`, `player/traits.ts` `getAiTraitValueFactor`. Tests: `aiValue.test.ts`, `aiTraitValue.test.ts`.
- **Details:** `docs/player-traits.md` (data model, hook table, how the sim applies each hook, calibration).

### Injury depth

- **Setting:** `injuryDepth`. On for new leagues, off for existing leagues (they play exactly as before).
- **What:**
  - **Minutes restriction on return:** after an injury of 5+ games, a player comes back on a restriction for about a third as many days (2–10), starting at ~55% of his normal playing-time weight and easing back to 100%. It goes through the same knob as the roster page's playing time setting, so the rotation code respects it.
  - **Re-injury risk:** for 15 days after any injury of 2+ games the injury risk is higher (up to 1.8×, fading), and a new injury has a 45% chance to be to the same body part.
  - **Injury-prone players:** about 7% of players (fixed per player), plus anyone with 5+ injuries of 3+ games in the last three seasons, get hurt 1.4× as often. Shown as a badge on the player page.
  - **Back-to-backs:** the second night of a back-to-back (regular season) has 1.15× injury risk and slightly lower endurance (more fatigue in the game). Marked **B2B** on Schedule and Daily Schedule.
  - **Load management:** on the second night of a back-to-back, AI teams rest veterans in their top 8 (34+, or 31+ and injury prone) when they have at least 10 healthy players. For your team, turn it on for the whole team on the Roster page (below Play Through Injuries) or for single players on their player pages.
  - Everyone's base rate is scaled by 0.9 so league-wide totals stay about the same.
- **Player page:** the Injuries section adds a body-part history (injuries, games missed, last season) and, with the setting on, the restriction / recently returned / injury-prone status and the load management checkbox.
- **Known limits:** the countdowns are per day (like BBGM's injury countdown), not per game played. Resting is decided when the teams are loaded, so a rested player shows as not playing in the box score. With player traits on, a player's durability trait multiplies his injury rate on top of this.

### Season odds

- **Where:** _Standings_ (a _Season odds_ section below the tables), _Power Rankings_ (Playoffs and Title columns), _Award Races_ (a Win% column), _Draft Lottery_ (a _What-if simulator_ below the lottery table).
- **What:** 1,000 Monte Carlo simulations of the rest of the season in the worker: each remaining game is decided from team strength (team rating from the current roster, ignoring injuries of 10 days or less, blended with point margin as games are played) plus home court, playoffs are seeded with the game's own playoff code, then the play-in and the bracket are played out. Gives projected record, playoff and play-in odds, seed distribution, reaching the semifinals/finals and title odds. During the playoffs it plays out the remaining series from the current state. Results are cached and refreshed after each day of games, trades, signings or injuries (about 0.2 s per refresh), and only when a page that shows them asks.
- **Award races:** each candidate's award score (BBGM's award scoring) is projected to the end of the regular season with noise that shrinks as the season goes on, and the winner drawn 5,000 times.
- **Lottery what-if:** move teams up or down the lottery order (chances stay with the slot) or pick another lottery format, then _Run lottery_ for exact odds (where fast enough), a 20,000-lottery simulation (hover a cell) and one sample draw.
- **Known limits:** current season only. Tiebreakers are approximated (random among tied teams) and playoff reseeding is ignored. Award odds only consider the top 10 candidates shown and don't model team record changes. The what-if ignores nba2027 restrictions and COLA when switching formats; in the other sports (no Season Odds there) it goes with the _Extra frivolities_ switch.

## Players

### Archetypes

- **What:** a 2K-style archetype for every basketball player (186 of them: Floor General, Sharpshooter, 3-and-D Wing, Stretch Four, Rim Protector, Point Center, Jumbo Playmaker, Corner Specialist, Stretch Rim Protector, Point of Attack Defender, Three-Level Scorer, Two-Way Stretch Big, ... plus role players (Backup Point Guard, Rotation Wing, Backup Center, Journeyman ...), raw prospects (Raw Athletic Wing, Project Big, Shooting Prospect, ...), veterans (Veteran Floor Leader, Crafty Veteran Guard, Veteran Big, ...) and rare "unicorn" types), **derived from his actual ratings**, with an optional hybrid partner ("Slasher / Playmaker"), a tier by overall within the league, a confidence and a "why" (the three ratings groups that fit best). Engine: `src/common/archetypes/` (profile scoring over BBGM's composite ratings, height gates, **position priors**, signature skills, league percentiles).
- **Position prior:** his BBGM position (PG, G, SG, GF, SF, F, PF, FC, C; the game's own formula or, with [Improved positions](#improved-positions), the two-axis model, both in `position.ts`) is a strong prior. Each group (guard/wing/forward/big) has a per-position nudge, archetypes can override single positions (a Big Guard may be a GF, a Small-Ball Five an F), and some pairings are never allowed whatever an archetype says: PG/G/SG/GF are never bigs, PG/G never forwards, F/PF/FC/C never guards. A player's match is read against his peers (same height gate, allowed positions), and the stored label uses the position the game shows, so scouting fuzz cannot push him across. The calibration that evens out how often each archetype is picked is capped at ±0.25 (it was ±0.6): correctness over evenness. In a small league, an archetype with too few peers reuses the reference league's table instead of being read against everyone (that was what labelled some point guards Towering Center). Diagnostics: `RUN_ARCHETYPE_DIAG=1` on `diag.script.test.ts`.
- **A label must deliver what its name says (defining-skill gates):** every dimension an archetype weights at 2 or more must actually be there (at least ordinary for his size and above his own norm), and names carry absolute floors (`NAME_NEEDS` in `defs.data.ts`): a shooting label needs real three-point shooting, a rim protector real shot blocking (not just height), a playmaker real passing, an athletic label real athleticism, rebounding/post/slashing labels the skill for his size. A shortfall costs fit in proportion (`score.ts`), so the label goes to the next archetype that does fit. Prospects well below the league's level get proportionally lower floors (a promising shooter at 19 is still a shooter). Being even better than a profile asks at a skill it wants no longer counts against a fit (an elite shooter is still a shooter), and size-driven skills (blocks, interior defense, rebounding, rim and post scoring) are read partly in absolute terms.
- **Lifecycle archetypes:** raw prospects and journeymen are gated on his overall level (well below the league's), raw prospects also on age (24 or younger); veterans need his age (31+, never picked when the age is unknown, so not for draft prospects or regeneration targets). Their tables always come from the reference league, which includes a draft class of prospects.
- **Calibration:** `calibrate.script.test.ts` evens shares within each group (guard, wing, forward, big), trims catch-all role types harder and never pushes lifecycle types up. Diagnostics: `RUN_ARCHETYPE_DIAG=1` on `diag.script.test.ts` (random league, aged veterans, draft prospects, real NBA ratings 2016-2025 from `data/`, year-to-year stability; an independent label-vs-ratings audit). Before/after this retune: label-vs-ratings mismatches 10.9% → 0.7% of a random league (real NBA ratings 13.4% → 1.2%, draft prospects 61% → 0.3%), no archetype above 2.5% of a random league, 0 hard position conflicts, year-to-year changes about the same (13.5% → 14.1% of seasons).
- **Stored per preseason:** the label is saved on the player (`p.archetypes`, one entry per season) when the preseason phase begins, after development, so it holds all season and his history of changes is kept (it travels in league files; only the current entry is shown, the per-season list is kept internally). New leagues get a first entry for everyone; older leagues and players without an entry fall back to a live reading (stored the first time the player page is opened). Prospects are always read live, since their ratings can be regenerated. With the switch off nothing is stored or computed.
- **Where:** the player page (_Archetype_ line with a why popover, replacing _Build_; no history is shown), Draft Scouting (_Archetype_ column), Advanced Player Search (_Archetype_ filter), the roster page (_Roster composition_ panel with balance warnings) and League → _Archetypes_ (`/l/:lid/archetypes`: counts and best players).
- **Regenerate ratings:** prospects can be aimed at an archetype (per prospect, or a class pool). It uses the same solver, so overall, potential and height stay exact; the preview shows the archetype the new ratings actually derive to (a check mark when it is the one asked for). The 447 builds are still available under _Advanced: build_.
- **Known limits:** archetypes use scouting-fuzzed ratings (like skills and positions), so they can differ slightly from the true ones; aiming at a very specific archetype succeeds about three to four times in five at a given overall (the class archetype pool only aims a prospect at archetypes his position allows). With the switch off, the Advanced Player Search still lists an (empty) Archetype column.

### Improved positions

- **What:** basketball positions (PG, G, SG, GF, SF, F, PF, FC, C) from two axes instead of BBGM's one PG-to-C line. **Size** = height (dominant) plus strength, rebounding, inside scoring, jumping and defensive IQ; **ball skills** = passing, dribbling, three point shooting, speed and offensive IQ. Each is turned into a percentile against a fixed reference distribution (generated players), so positions do not drift with the league. The nine positions are centroids in that square (PG small/skilled, C big/unskilled, FC a big with skills, PF a big without, F/GF/G hybrids) with a per-position bias fitted on sticky careers so overall shares stay within about half a point of the old formula. Tall playmakers become F/FC rather than C, small bigs PF/F. Code: `improvedPosition`/`positionFor` in `src/common/archetypes/position.ts`; fitting and diagnostics: `RUN_POSITION_FIT=1` on `positionFit.script.test.ts` (`FIT=1` refits the biases).
- **Stickiness:** when a player develops he keeps his current position unless another one is closer by a margin (0.02 in squared percentile distance). Position changes per player-season: about 5-6% (old formula ~6%, the two-axis model without stickiness ~13%).
- **When positions change:** for new players at generation, and when players develop (preseason, or a God Mode edit). Rows of earlier seasons are never rewritten. Custom string positions (`p.pos`) are untouched. As before, positions come from true ratings (not scouting fuzz).
- **Archetypes:** the stored position is the archetype prior (hard blocks unchanged: same nine labels); prospects' live labels and the ratings regenerator read the position the game would assign. Forbidden archetype/position pairings: 0; odd pairings 0.3% (0.8% with the old formula).
- **Setting:** on for new leagues, off for existing ones (off = the original formula, exactly). Turning it on in an existing league takes effect as players develop; mid-season, a player whose position is recomputed (e.g. a God Mode edit) may move to the new model before the preseason.
- **Known limits:** the archetype engine's built-in reference tables (`norms.data.ts`) were built with the old positions; league norms use the stored positions.

## Contracts, mood and player unrest

Unlike most of the pages above, these work in every sport. Switches are in League Extras; on for new leagues, off for existing leagues until turned on.

- **Options and partial guarantees** (_Contract Options & Guarantees_): the negotiation window has _Option_ (player option −5%, team option +10%) and _Guaranteed after year 1_ (100/75/50/0%, up to +20%) pickers for contracts of 2+ years. AI teams put terms in some of their deals too. Options are decided at the start of the re-signing phase: players opt out when the market pays more (or they're unhappy and wouldn't lose much), teams keep a team option if the player is worth about what he'd be paid. A declined option makes the contract expire then, so the player can be re-signed like any expiring contract. You can exercise or decline your own team option early from the player page. Releasing a player only owes the guaranteed part of seasons after the current one, and not an undecided team option. Contracts show a _PO_/_TO_/_%G_ badge next to the expiration year.
- **Extensions** (_In-Season Contract Extensions_): players in the last 2 seasons of their contracts can be extended in the preseason and regular season, from _Negotiate extension_ on the player page. The new seasons are added after the current ones, so this season's payroll doesn't change. Willingness comes from mood. AI teams extend some good players in their final season. Extensions can be undone like signings.
- **Mood transparency** (always on): the player page _Contract & Mood_ panel shows contract seasons with guaranteed amounts and options, release cost, a _What would make him re-sign?_ table (projected willingness if the team wins, after a deep playoff run, with a bigger role, with no more trades, or all of these), and mood history with sparklines. Mood is snapshotted at the trade deadline, at the end of the regular season and after the playoffs (up to 30 per player, in `p.moodHistory`).
- **Free agent demands** (always on): during free agency and the season, a free agent with no market comes down faster than the stock daily decrease (which is tiny next to modern salaries). Below replacement level (the median AI team's last-man value) he gives up half of what he asks above the minimum each day in the regular season (12% a day in free agency), so he's at the minimum within about 5 days. A better player who asks more than his share of AI cap space (the best free agent is matched with the most cap space any AI team with a roster spot has, the second best with the second most, ...) gives up 35% a day (8% in free agency, so about a week in the season), but not below that cap space, so players a team could still pay keep their price. Over-the-cap AI teams only sign minimum contracts in either cap mode; with no salary cap only below-replacement players drop fast. A free agent at the minimum still refuses a team he really hates (mood components summing below -8) until enough days unsigned bring him around. Code: `freeAgents/decreaseDemands.ts` (`getDemandMarket`); `FA_METRICS=1` on `decreaseDemands.test.ts` prints a day-by-day table.
- **Free agent market** (always on): the Free Agents page _Market_ column shows how many AI teams are interested and the chance he signs elsewhere on the next day; click it for each team's interest (top target, next in line, fallback), the per-day chance and the most likely team. This mirrors how AI teams sign free agents (each day, a team that doesn't skip signs the best player it can fit).
- **Trade requests** (_Trade Requests_): very unhappy stars (top 15% by value) can ask to be traded, checked about weekly in the regular season. It's in the news, AI teams value him 15% lower when trading him away, and the trading block shows a _Trade request_ badge. Requests end when he's traded, extended, or happy again.
- **Holdouts** (_Holdouts_, option _Holdout Frequency_, 0 for none): before the regular season, unhappy players paid well under their market value with 2+ seasons left may hold out, missing a few games (scaled to season length). An extension or a trade ends it early; holdouts also end with the regular season.
- **Data:** contracts gain optional `option`, `guaranteed` and `extensions`; players gain optional `moodHistory`, `tradeRequest` and `holdout`. Nothing needs migrating.
- **Known limits:** what-if projections hold everything else fixed. Market odds are for the next day only and assume teams keep their current needs. Holdout players sit out like injured players.

## Trades

Unlike most of the pages above, these work in **all sports** (the trade code is shared).

- **Why the AI said no** (_Trade Explanations_): on the Trade page, when the AI rejects a proposal or answers _What would make this deal work?_ with a counter, a _Why?_ link under the GM's message lists, per asset, the terms the AI used: talent level, age and strategy (rebuilding teams value youth and picks more, contenders discount potential), contract (overpaid/bargain/expiring; rebuilding teams weigh contracts more), injuries, projected pick position, plus team-level terms: strategy, roster fit (team ovr before → after) and payroll/cap space. Built from `ValueChangeCalculator.explain()`, the same math the AI decides with.
- **Need-driven AI-to-AI trades** (_Need-Based AI-to-AI Trades_): contenders buy veterans in the run-up to the trade deadline, rebuilding teams sell veterans for picks and young players, and teams paying luxury tax dump contracts into teams with cap space (with draft picks as sweeteners). Over-the-cap buyers send back salary filler. The reason is shown in the trade's transaction text. Off gives the classic random trades only; _AI-to-AI Trades Factor_ still sets the overall number of attempts.
- **AI offers to you / Trade Offers** (_AI Trade Offers To You_, options _AI Trade Offers Frequency_ and _AI Trade Offers Expiration_): replaces the stock _Trade Proposals_ page with a _Trade Offers_ inbox, `/l/:lid/trade_offers` (menu _Players → Trade Offers_, trade "More" links; `/l/:lid/trade_proposals` redirects there while the feature is on, and with it off the stock Trade Proposals page and menu item are back and `trade_offers` redirects the other way). AI teams send offers on their own: daily during the regular season (until the trade deadline) and free agency (chance frequency/10 per day), and at the start of the draft lottery, after-draft and re-signing phases (chance frequency/2). About 60% of the time an offer is for something on your trading block (when it has anything), otherwise an unsolicited ask from the team's strategy (contenders want good veterans, rebuilders young players and picks), filled out with `makeItWork` (AI adds only its own assets, pick protections allowed). Each new offer gets an inbox message and a notification. Each offer shows the team, what you give/get, its source (_Trading block_, _Unsolicited_, _You asked_), a value hint from your side (good / roughly fair / favors them) and when it expires; buttons _Accept_ (goes through the normal trade proposal, undoable), _Negotiate_ (loads it on the Trade page, pick conditions kept) and _Decline_ / _×_. _Request offers_ (the old trading block "what would you give") asks every AI team about the selected players/picks and keeps the 3 best answers in the inbox. Offers expire after _Expiration_ days (your games in the regular season, days of free agency), when the phase changes, when the AI team's roster changes, or when an asset in it moves; at most 8 are kept, one per team. Stored in the `aiTradeOffers` game attribute (new fields `daysLeft`, `rosterKey`, `source` are optional, so old leagues load as is). No unsolicited offers when AI trades are off (factor 0), in spectator mode, auto play or the no-trades challenge. Code: `trade/aiOffers.ts`, `views/tradeOffers.ts`, `ui/views/TradeOffers.tsx`.
- **Trade Market** (_Trade Market_): _Players → Trade Market_, `/l/:lid/trade_market`, linked from the Trade page, Trade Proposals / Trade Offers and the "trade deadline is coming" notification (a week before the deadline). Lists players each AI team is willing to move (0–100, from strategy, age, contract and role on the team, with reasons) and an asking-price hint relative to the team's own next first round pick.
- **Three-team trades** (_Three-Team Trades_): `/l/:lid/trade_three/:tid1-:tid2`, linked from the Trade page (_3-team trade_). Send any player or pick from any team to any other team. Each AI team must like what it gets (with the same _Why?_ explanations) and the salary cap rules apply to each team's total incoming and outgoing salary; during the season rosters can't go over the maximum. An accepted trade is recorded as one regular trade event per pair of teams that exchanged something, each noting it was part of a three-team trade, so trade summaries and transactions work as usual. Undo is supported. The regular 2-team Trade page is unchanged.

### Draft pick protections and swaps

_Draft Pick Protections & Swaps_ (`featureDraftPickConditions`, all sports; on for new leagues, off for existing ones).

- **Adding a condition:** on the Trade page, every pick in the trade summary has a _+ protection/swap_ link (on the 3-team trade page, once the pick has a destination). Choose:
  - **Top-N protected** (1st round picks only): if the pick lands in the top N of its round, the team that traded it keeps it. _Then next years_ is the protection for each following year (e.g. `8, 5`), and _After that_ is what happens when the last one is protected too: the next year's pick conveys **unprotected**, it **converts to a 2nd round pick** (next year's 2nd rounder of the same team) or it is **extinguished**.
  - **Swap rights only**: the pick stays where it is, the receiving team gets the right to swap its own pick in that draft and round for it, if it's better.
- **Where it shows:** pick descriptions everywhere (trade asset lists, summaries, trading block, proposals, Draft Picks page with a badge; swap rights a team holds are listed on its Draft Picks page), the transaction/news text and Trade Summary page of the trade ("top 10 protected (then top 8, then unprotected)", "the right to swap 2027 1st round picks").
- **Resolution:** when the draft order is set (after the lottery, or at the start of the draft), swaps are executed if the other pick is better, protected picks convey or go back to the original team, and the obligation rolls over to the next season's pick of the same team (or converts/extinguishes). Each outcome is a news event (type `draftPickCondition`) with a notification for your team. If the pick a protection would roll over to was traded away in the meantime, the obligation is extinguished (noted in the event).
- **AI:** conditional picks are valued by their expected value: the chance of each pick slot (projected standings, simulated season odds and lottery odds, as for any pick) is split into conveyed/protected, with a discount for what's owed instead (rollover 60%, unprotected next year 75%, 2nd rounder 12%, extinguished 0). Swap rights are worth E[max(own pick, other pick)] − E[own pick]; a pick carrying someone else's swap right is worth E[min]. When the AI rejects an offer that includes its own 1st round picks, _What would make this deal work?_ first tries protecting them (top 3/5/8/10/14, one rollover year, then unprotected) and proposes the smallest protection that works.
- **AI trades with conditions:** in AI-AI trades (random and need-based), AI trade offers to the user and when it fills out a trade, an AI team may give its own picks with conditions: each step, up to two of its picks also get a variant with a protection drawn from a menu (top 3 → top 3 then unprotected; top 4 → 2nd rounder; top 5 → 5, 3 then unprotected; top 8 → 5 then 2nd rounder; top 10 → 2nd rounder; top 10 → 8 then extinguished; top 14 → 10, 5 then unprotected; only tops below half a round) and, when the partner owns its own pick in that draft, a swap-rights-only variant. They compete with every other asset on value, so they are used when they fit the balance best; rebuilding teams prefer the protected version (counted as if 40% smaller dv). Offers show the condition in the pick description and keep it when you open the offer on the Trade page. The Trade Market's asking price adds how much a top 5 protected first from you counts for compared to an unprotected one. Code: `trade/makeItWork.ts` (`aiPickConditions`, `getConditionVariants`).
- **AI asks for terms on your picks:** when the AI receives picks with conditions from the other team (Trade page _What would make this deal work?_, trading block / AI offers, AI-AI trades), `makeItWork` also tries changing the terms on those picks as candidate assets, valued like any other: when it wants more, loosening a protection the other team added (dropping the last rollover year, falling back to unprotected instead of a 2nd rounder/extinguished, lowering top-N to 8/5/3/1, or removing it); when it's getting more than it needs and the user's side can change, accepting a top 3/5/10 protection on an incoming 1st. The usual forward selection picks the smallest change that balances. The Trade page message says what changed ("They want the top 10 protection on your 2027 1st round pick lowered to top 5.", "...removed.", "They'll accept top 5 protected on ..."), and offers show/keep conditions on your picks (`tradeFor` `userPickConditions`). Only conditions added in the trade can change (existing ones on stored picks can't). Code: `getPickTermsVariants` in `trade/makeItWork.ts`, `getProtectionLoosenings`/`pickConditionChangeText` in `common/draftPickConditions.ts`, `getPickTermsMessages` in `trade/makeItWorkTrade.ts`; tests in `trade/pickTerms.test.ts`.
- **Changing a protection already on a pick:** a pick with a protection from an earlier trade can have that protection lowered or removed when it moves again, if the team holding the protection (the one that keeps the pick when protected) is also in the trade and isn't the one receiving the pick. In practice that's a 3-team trade; in a 2-team trade that team is never a party, so stored protections are only valued, not changed. In a trade it's a condition with `amend: true` (top 0 = removed). Valued with the new protection and the protecting team as fallback owner, applied in `processTrade` (text "protection changed to ..."/"protection removed"), and undo restores the old protection (not once the draft order is set). Validation: `validatePickConditionSpec(spec, dp, n, { participants, toTid })`.
- **3-team "What would make this work?":** button on the 3-team trade page. AI teams that don't like the trade ask for the smallest changes to the terms of picks they receive: loosening protections added in the trade, and loosening stored protections held by your team (not ones held by another AI team, which would lose value it isn't paid for). Greedy, up to 8 steps: a change that makes every AI team accept with the smallest gain, else the smallest change that gets the unhappy teams closer. The page shows "Team: We want the top 10 protection on your 2027 1st round pick lowered to top 5." etc.; a changed stored protection has a _keep existing_ link to undo the ask. Code: `makeItWorkMulti` in `trade/multiTeam.ts` (API `makeItWorkMultiTeamTrade`).
- **Starting protections:** in AI offers to you and random AI-AI trades, a 1st round pick the AI asks for starts with a protection from the AI menu 35% of the time (`withStartingProtections`, `STARTING_PROTECTION_PROB`), so the AI then asks to loosen it or keeps it (the offer text says "your 2027 1st round pick (top 5 protected)").
- **Valuation of what's owed:** the rollover / 2nd round pick owed instead of a protected pick is weighted by the chance it is delivered: 0 if the original team no longer owns it (or it is in the same trade, or already has a condition), 90% if it owns it (it could still trade it later), 90% if it isn't generated yet. Swap rights are discounted 10% for lapse risk (and worth nothing if the swapping team's own pick moves in the same trade); a pick carrying someone else's swap right is valued 90% swapped, 10% as itself. `getFallbackDeliveredProb`, `CONDITION_SURVIVE_PROB` in `ValueChangeCalculator.ts`.
- **Storage:** `draftPicks[].protection = { tid, top, rollover, then }` (tid = team that keeps it if protected) and `draftPicks[].swap = { tid }` (team holding the right), in the league file too (JSON schema updated, no DB migration needed). Pending conditions in a trade are `trade.teams[i].pickConditions`. Code: `common/draftPickConditions.ts` (text/validation), `worker/core/draft/pickConditions.ts` (resolution, called from `genOrder`), `processTrade` (apply/undo), `ValueChangeCalculator` (valuation), `trade/tryProtections.ts` (AI counters).
- **Limits:** one condition per pick; conditions can't be added to a pick that already has one, or once the draft order is set; swap rights themselves can't be re-traded (the pick carrying them can, and the right stays with the team); no "least favorable of" picks.

## Draft and scouting

### Draft Scouting

- **Where:** _Players → Draft → Draft Scouting_ (`/l/:lid/draft_scouting`).
- **College and overseas stats** (_College & Overseas Stats_): the _College stats_ button above each draft class generates college (or overseas pro club) stats and honors for its prospects from a seed (same seed, same result), or regenerates/removes them. They show on the player page with a _College_ or _Overseas_ tag in the stats tables and an _Earlier honors_ box, and are **not** pro stats: they don't count toward experience, career totals, awards, Hall of Fame or player value. The option _Generate Pre-Draft Stats Automatically_ does it for every new draft class (all classes at league creation, each season's new class, fantasy/expansion/custom classes, and imported prospects who have none). _All draft classes_ panel: the same for every upcoming class at once (seed, only prospects without stats or replace everyone's).
- **Regenerate ratings** (_Ratings Regenerator_): rebuilds prospects into specialized builds or archetypes (Floor General, Stretch Big, Rim Protector, …) without changing overall, potential or height. Scope: whole class, selected prospects, one prospect, or all classes at once (a preview summary per class, one _Undo last apply_ for all of them, and _Restore originals_). Settings include seed, variation, class flavor and strength, builds per class, archetype diversity, specialization and rookie caps, each lockable; per-player reroll and rating locks; preview with diffs; _Apply_, _Undo last apply_ (until reload) and _Restore originals_ (survives reloads). _Save as league default_ keeps the settings for _Re-randomize New Draft Classes_ (option; ratings first, then pre-draft stats; seeded from the league and class year; drafted players are never touched).
- **Scouting system** (_Scouting System_): your scouting budget gives you scouting points every season to spend on individual prospects: assign a scout (1 point) or attend a workout (3 points) in the _Scout report_ column. Each narrows how far off your view of that prospect's ratings can be and gives a scout report with ovr and pot ranges, a confidence and notes. Prospects you don't scout keep the normal rating fuzz.
- **Columns:** _Archetype_ (with the Archetypes switch), _Traits_ (with player traits), badges.

### Draft board and AI drafting

- **Draft Board** (_Draft Board_): `/l/:lid/draft_board[/:season]`, linked from Draft Scouting and the Draft page. Rank your prospects, give them tiers and notes next to their pre-draft stats, builds and scout reports. Option _Auto Draft From My Board_: when auto drafting for you, the top-ranked available prospect on your board is picked. The Draft page also has a _Draft-day trades & team boards_ window (trades through the trade API, each AI team's needs and board).
- **AI drafts by need** (_AI Drafts by Need_, basketball): AI picks get a small need (guard, wing, big) and strategy (contenders want players who are ready, rebuilding teams want ceiling) adjustment on top of value, at most about 2 value points (`draftNeeds.ts`; value still decides most picks). Off: the old pure-value drafting.

### Customize Player: Regenerate build

- **Where:** a player page → _Edit_ (`/l/:lid/customize_player/:pid`), _Regenerate build_ button (opens a dialog).
- **What:** the same build engine for one existing player: preview, pin ratings, reroll; keeps ovr, pot and height.

## Coaching staff

- **Where:** Team menu → _Coaching Staff_ (`/l/:lid/staff`, `/l/:lid/staff/:team`), League menu → _Coaches_ (`/l/:lid/coaches[/:season]`: head coaches, the season's coaching carousel, Coach of the Year history), and a page per coach (`/l/:lid/coach/:cid`). Team Finances links to the staff instead of offering the coaching slider.
- **What:** every team has a head coach and three assistants (player development, offense, defense) with ratings (development, offense, defense, motivation), a style (pace, threes, defense, rotation, each -1 to 1), age and a contract. Salaries are paid as coaching expenses (not against the salary cap). The staff's development score is turned into an equivalent coaching budget level, so it replaces the coaching budget's effect on progs, normalized by the league's average staff each time levels are synced, so the league-wide development effect stays centered like default AI coaching budgets while the coach pool's ratings drift over the decades (see `staff.test.ts` and [rating-inflation.md](rating-inflation.md)). After the playoffs each season: records are written to each coach (a coach hired or fired during the season gets only the games he was in charge of), Coach of the Year is awarded, coaches age/improve/retire, contracts expire, AI teams fire (losing head coaches especially) and hire from the pool (bigger markets pay more). Your expiring coaches leave unless you _Extend_ them; firing pays half the remaining contract as a buyout. Any vacancy still open in the preseason is filled automatically.
- **Setting:** `coachingStaff` (basketball only). On by default for new leagues; existing leagues (DB version 76 migration) and league files from before version 76 keep the slider until it's turned on, which generates staffs.
- **Storage:** `coaches` object store (key `cid`, index `tid`), included in league export under _All team data_.
- **For other features:** `src/worker/core/staff/data.ts` has `getTeamCoachStyle(tid)` (for team strategy / game sim later), `getCoachingCarousel(season)`, `getHeadCoachForSeason(tid, season)` and `getCoachAwards(type)`.
- **Known limits:** no in-game effects yet (style is exposed only). Scouts and trainers are not modeled. With the budget disabled, every team gets the average development effect, as with the slider.

## Known limits (all features)

- Basketball only unless a section says otherwise; the other sports hide the menu items and links.
- The Wrapped, Storylines and Timeline pages share a whole-history snapshot that takes a while the first time in a big league.
- The league-wide averages with player traits, the possession model or injury depth on stay about the same as with them off, but individual games and seasons are of course different; use the switches (off) to replay the old behaviour.
- Existing leagues keep playing as before until the game-affecting switches (possession model, traits, injury depth, contracts, trades, drafting, coaching staff) are turned on in League Extras. Games already played replay unchanged.
- Draft board and scouting need prospects: the Draft Board is empty in a league without upcoming classes.

## Performance

Wrapped and Storylines read the whole league into a snapshot. Converted pieces that can't change any more (retired players, finished seasons' box scores and team seasons) are cached in a separate IndexedDB database (`wrapped-cache`), versioned by the converter code and invalidated through the league's change log, so later sessions only read what changed. Idle snapshots are evicted from memory. `tools/perf/wrapped/` holds the Playwright benchmark scripts (see the header of `bench.cjs`).
